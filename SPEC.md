# Spec: waifu-companion

## Objective

An anime-style AI companion named **Cyrene** (renamable in `config.yaml`) that
listens through one USB mic on the owner's Windows PC, responds **only to the
owner's voice**, chats in Indonesian with Japanese phrases, and controls the
house: Tuya Wi-Fi lights and plugs, an IR blaster (Broadlink or Tuya) for the
Samsung AC, Wanbo Dali projector, and TV, and the PC itself.

Hardware budget is ≤ Rp1 juta, so there is no always-on hub: the PC runs
everything. Turning the PC *on* is out of scope for the voice loop (the owner
uses a smart plug + BIOS "power on AC restore" or Wake-on-LAN from a phone).

Since v1.4 she is also the owner's companion for the HoYoverse games they play
every day (Honkai: Star Rail, Genshin Impact, Zenless Zone Zero, Asia server):
live status, reminders by voice and phone push, the HoYoLAB daily check-in, and
pull history with pity (see "gacha buddy (v1.4)").

### User stories

1. "Cyrene, nyalakan lampu kamar" → light turns on, she answers in voice within ~3 s of the owner finishing speaking (local STT + LLM on the RTX 5060 Ti).
2. "Cyrene, AC dua puluh empat derajat dan matikan proyektor" → two device calls, one spoken summary.
3. Right after she answers, "terus nyalakan TV juga" works without the wake word (follow-up window).
4. A guest saying "Cyrene, matikan lampu" is ignored (speaker verification).
5. "Cyrene, matikan komputer" → she asks for confirmation first; on "iya" Windows schedules a 30 s shutdown that "batalkan" can cancel.
6. Without any hardware or GPU, `waifu chat --dry-run` lets the owner type and test the persona and tool calls against fake devices.

## Capability map

| Module id | Responsibility | Depends on |
|---|---|---|
| config | Typed `config.yaml` (done: `src/waifu/config.py`) | — |
| devices | Device contract, registry, Tuya, Broadlink, PC, mock, IR code store | config |
| brain | Tool specs from the registry, persona prompt, Claude and Ollama backends | config, devices |
| voice | Mic/speaker I/O, utterance segmenter, speaker verification, STT, TTS | config |
| notify | Push notifications to the owner's phone through ntfy (v1.4) | config |
| gacha | HoYoLAB status and check-in, gacha history and pity, reminders, the game tools for the brain (v1.4) | config, notify, brain (`ToolSpec`, `ToolProvider`) |
| app | Wake gate, listen → verify → transcribe → think → speak loop, CLI | all |

Build order: config → devices, voice → brain → app. `devices` and `voice` are
independent; `brain` only needs `devices.registry`'s public surface. v1.4 adds
config → notify → gacha → app; `gacha` reaches the brain only through the
`ToolProvider` protocol in `brain/tools.py`, and the voice loop only through
`Assistant.announce`.

## Tech Stack

Python 3.14 venv at `.venv` (3.11+ supported). Core: `anthropic` 1.13, `ollama`
0.6, `pydantic` 2, `pyyaml`, `numpy` 2, `tinytuya` 1.20, `broadlink` 0.19,
`wakeonlan` 4, `edge-tts` 7, `soundfile`, `sounddevice`. Voice extra:
`faster-whisper` 1.2 (+ `ctranslate2`), `speechbrain` 1.1, `torch`/`torchaudio`
from the cu128 index (RTX 50-series needs CUDA 12.8+ builds). v1.4 adds `genshin`
(genshin.py) 1.7.31 to the core (unofficial HoYoLAB client, async on `aiohttp`,
which edge-tts already brings; only `tenacity` is new besides it).

## Module contracts

The abstract contracts are already committed in `devices/base.py`,
`brain/base.py`, and `voice/base.py`. The concrete public surface below is what
other modules may rely on.

### devices

- `devices/mock.py` — `MockDevice(device_id, name, aliases=None, commands=None, kind="mock")`. Accepts any listed command (default `["on", "off"]`); like `IrDevice`, a `value` with a listed `f"{command}_{value}"` resolves to that command. Records `calls: list[tuple[str, int | None]]` (resolved command, value), updates `state["power"]` for on/off and `state["last_command"]`, returns ok results. Unknown commands raise `DeviceError`. Used by tests and `--dry-run`.
- `devices/ir_codes.py` — `IrCodeStore(path)`: JSON file `{device_id: {command: base64}}`. `get(device_id, command) -> str | None`, `commands(device_id) -> list[str]` (sorted), `put(device_id, command, code)` writes atomically (temp file + `os.replace`), creates the parent folder. Command names must match `^[a-z0-9_]+$`.
- `devices/tuya.py` — `TuyaLight` (commands `on`, `off`, `toggle`, `brightness` with value 1–100), `TuyaPlug` (`on`, `off`, `toggle`), `TuyaIrBlaster` (send/learn base64 codes via `tinytuya.Contrib.IRRemoteControlDevice`). Each takes a `TuyaConnection` and an injectable factory for the tinytuya object; connections are created lazily on first command and use a short socket timeout (≤ 5 s). Tuya error payloads (dicts with `Error`/`Err`) become `DeviceError`.
- `devices/broadlink_ir.py` — `BroadlinkBlaster(host, *, factory=broadlink.hello)`: lazy `auth()`, `send(code_b64)`, `learn(timeout_s=20) -> str` (enter learning, poll `check_data()` until data or timeout). Reconnects once on a socket/auth error.
- `devices/ir_device.py` — `IrDevice(device_id, name, aliases, blaster, store)`: commands are the learned names in the store. `execute(command, value)`: if `value` is given and `f"{command}_{value}"` is learned, send that (so `temp` + 24 → `temp_24`); unknown commands raise `DeviceError` listing what is learned. Tracks `state["last_command"]`. Blaster protocol: `send(code_b64) -> None`, `learn(timeout_s) -> str`.
- `devices/pc.py` — `PcDevice(device_id, name, aliases, conn: PcConnection, *, run, send_wol, suspend, timer_factory)`. Commands: `wake` (needs `mac`), and when `conn.local`: `shutdown` (`shutdown /s /t <delay>`; Windows force-closes apps when the delay is > 0, and the reply says so), `restart` (`shutdown /r /t <delay>`), `cancel_shutdown` (`shutdown /a`, also cancels a pending sleep), `sleep` (PowrProf `SetSuspendState(0, 0, 0)` via ctypes — never rundll32, which cannot pass arguments and hibernates — delayed by a ~5 s daemon timer). **Power interlock:** when `WAIFU_DISABLE_POWER` is set to anything but `0`, every real power call refuses; the test suite sets it in `tests/conftest.py`, which also refuses `shutdown`/`rundll32`/PowrProf in every test.
- `devices/registry.py` — `DeviceRegistry(devices)`: `get(id) -> Device | None`, `all() -> list[Device]`, `describe_all() -> list[dict]`, `execute(device_id, command, value=None) -> DeviceResult` which **never raises** (unknown device, unknown command, `DeviceError`, timeouts, and unexpected exceptions all become `ok=False` with an Indonesian message; unexpected ones are logged with traceback). `build_registry(config: AppConfig, *, dry_run=False) -> DeviceRegistry`: one blaster instance per IR host/Tuya id shared by every IR device on it; `dry_run` swaps every device for a `MockDevice` with the same id, name, aliases, and commands, keeping the real `kind` (IR commands = learned codes ∪ the device's declared `commands`, PC commands from its type and `local` flag). No network or subprocess call happens while building, in either mode.
- For `ir` devices, `DeviceConfig.commands` declares the commands the owner *intends* to learn (e.g. `on`, `off`, `temp_16`…`temp_30`). Real mode only exposes learned ones; `waifu check` lists declared-but-unlearned commands and `waifu learn-ir <id> --missing` walks through them.

### brain

- `brain/tools.py` — `build_tool_specs(registry) -> list[ToolSpec]` with exactly two tools:
  - `control_device` `{device: enum[device ids], command: string, value?: integer}` — description lists each device's commands so the model picks valid ones.
  - `list_devices` `{}` — returns current `describe_all()`.
  Schemas use `additionalProperties: false`, no numeric `minimum`/`maximum` (unsupported by strict tool use). `run_tool(registry, name, arguments) -> tuple[str, bool]` returns a compact JSON string (`ensure_ascii=False`) and `is_error`; unknown tools and invalid arguments are errors, never exceptions. `to_anthropic(spec)` adds `strict: True`; `to_ollama(spec)` returns `{"type": "function", "function": {...}}`.
- `brain/persona.py` — `build_system_prompt(persona_text, assistant_name, registry) -> str`: persona with `{name}` filled, plus a stable device list (id, name, aliases, commands — no live state). `format_user_turn(text, now) -> str` prefixes `[<Indonesian weekday>, DD-MM-YYYY HH:MM]` so the model knows the time without editing the system prompt. `load_persona(path) -> str`.
- `brain/session.py` — `SessionClock(idle_minutes, max_turns, clock=time.monotonic)`: `should_reset() -> bool`, `record_turn()`, `reset()`. Shared by both backends.
- `brain/claude.py` — `ClaudeBrain(config: BrainConfig, registry, system_prompt, *, client=None, clock=...)`. Uses `client.beta.messages.create` with model `config.claude.model`, `max_tokens`, `output_config={"effort": ...}`, adaptive thinking by omission, strict tools, top-level `cache_control={"type": "ephemeral"}`, and when `config.claude.fallbacks` is on `betas=["server-side-fallback-2026-07-01"]` + `fallbacks="default"`. Manual tool loop up to `max_tool_rounds`; all tool results of one round go back in a single user message. History is **append-only** within a session (preserved-thinking rule): always append the full `response.content`; never edit or trim earlier turns; when a session should end, start a new empty one. Before echoing a response that contains a `fallback` block, drop `thinking`/`redacted_thinking`/`tool_use` blocks that precede the last `fallback` block. A failed turn (API error) is rolled back by truncating to the length before the turn, then a short Indonesian apology is returned. `stop_reason == "refusal"` → apology, turn rolled back. `pause_turn` → resend. Text is the concatenation of `text` blocks of the final response.
- `brain/ollama_brain.py` — `OllamaBrain(config: BrainConfig, registry, system_prompt, *, client=None, clock=...)`. `ollama.Client(host).chat(model, messages, tools=[to_ollama...], think=config.ollama.think, keep_alive=...)`; tool calls from `response.message.tool_calls`; tool results appended as `{"role": "tool", "content": ..., "tool_name": ...}`. Same session, rollback, and apology rules. Strips any `<think>...</think>` text from the final reply.
- `brain/factory.py` — `build_brain(config: AppConfig, registry, *, persona_text=None) -> Brain` (persona read from `assistant.persona_file` when not given). Since v1.6 also `providers` and `memory_section`, and `system_prompt` may be a callable read once per session (see long-term memory).

### voice

- `voice/audio.py` — `list_devices() -> str`, `resample(audio, src_rate, dst_rate) -> np.ndarray` (linear interpolation, float32), `MicStream(sample_rate, frame_ms, device=None)`: context manager; opens `sounddevice.InputStream` at the device's default rate and resamples to `sample_rate`; `frames()` yields fixed-size float32 frames; `pause()`/`resume()` drop audio while the assistant speaks (half-duplex, so she never hears herself). `Player(device=None)`: `play(audio, sample_rate)` blocking.
- `voice/segmenter.py` — `EnergySegmenter(sample_rate, vad: VadConfig, clock=time.monotonic)`: `feed(frame) -> Utterance | None`. Adaptive noise floor (slow EMA of non-speech frame dB); a frame is speech when its dB ≥ max(`threshold_db`, floor + `margin_db`). Keeps `pre_roll_ms` before onset, ends after `silence_ms` of non-speech, force-ends at `max_speech_s`, drops bursts shorter than `min_speech_ms`. `reset()` clears state.
- `voice/speaker.py` — `SpeakerVerifier(embedder: SpeakerEmbedder, voiceprint_path, threshold)`: `enrolled`, `enroll(samples, sample_rate)` (mean of L2-normalised embeddings, renormalised, saved with `np.save`), `score(audio, sr) -> float` (cosine), `verify(audio, sr) -> tuple[bool, float]`. `EcapaEmbedder(model_source, model_dir, device)`: lazy speechbrain `EncoderClassifier.from_hparams(..., run_opts={"device": ...}, local_strategy=LocalStrategy.COPY)` (Windows has no symlinks without admin), resamples to 16 kHz, returns a 1-D numpy embedding.
- `voice/stt.py` — `WhisperStt(config: SttConfig, assistant_name, *, model_factory=None)`: lazy `faster_whisper.WhisperModel(model, device, compute_type, download_root)`; before loading on Windows, register CUDA DLL folders from the `nvidia-*` pip packages and `torch/lib` with `os.add_dll_directory` when present. `transcribe` resamples to 16 kHz, runs with `vad_filter=True`, `condition_on_previous_text=False`, an `initial_prompt` containing the assistant name, auto language; if the detected language is not in `config.languages`, re-runs with `languages[0]`. Drops known Whisper hallucinations (e.g. "Terima kasih telah menonton", "ご視聴ありがとうございました", subtitle credits) and returns an empty transcript for them.
- `voice/tts.py` — `split_by_language(text, default="id") -> list[tuple[str, str]]`: runs of Japanese script (hiragana, katakana, CJK ideographs, Japanese punctuation, long-vowel mark) become `"ja"`, everything else the default; neighbouring punctuation/space stays with the current run; empty runs dropped. `clean_for_speech(text)` removes emoji, markdown, and `*actions*`. `EdgeTts(voice: EdgeVoiceConfig)` (async `edge_tts.Communicate(...).stream()` collected in a sync wrapper, MP3 decoded with `soundfile`). `GptSovitsTts(voice: GptSovitsVoiceConfig, *, http_get=...)` (GET `{url}/tts` with `text`, `text_lang`, `ref_audio_path`, `prompt_text`, `prompt_lang`, `speed_factor`, `media_type=wav`). `SpeechRouter(engines: dict[str, TextToSpeech], default_language)`: `synthesize(text) -> tuple[np.ndarray, int]` cleans, splits, synthesises each run with its language's engine (falling back to the default language's engine), resamples to one rate, joins with 120 ms of silence. `build_speech_router(config: TtsConfig)`.

### app

- `gate.py` — `WakeGate(wake_words, followup_seconds, clock=time.monotonic)`: `check(text) -> GateResult(accepted, command)`. Normalises (lowercase, strip punctuation), matches a wake word anywhere with fuzzy tolerance (difflib ratio ≥ 0.8 per word, so "syrene"/"cyrene" match; wake words containing Japanese script match as substrings because Japanese has no spaces), removes it from `command`. Inside the follow-up window any text is accepted unchanged. `open_followup()` after each spoken reply; `close()`.
- `app.py` — `Assistant(config, *, brain, stt, speech, player, gate, verifier=None, speaker_check=True, now=datetime.now)`: `handle_utterance(utt) -> str | None` (verify owner → transcribe → gate → brain → speak → open follow-up; returns the reply text or None when ignored; a bare wake word gets a short acknowledgement like "はい, Master?"), `handle_text(text) -> BrainReply`, `run(mic, segmenter)` (loop with mic paused while speaking; Ctrl+C exits cleanly). Logs each decision (rejected speaker with score, gate reject, transcript, tool calls).
- `cli.py` — `main(argv=None) -> int`, subcommands: `run`, `chat [--speak]`, `enroll [--samples 6 --seconds 4]` (prompts Indonesian phrases to read aloud), `speaker-test` (live scores vs threshold), `devices`, `device <id> <command> [value]`, `learn-ir <device_id> <command>` or `learn-ir <device_id> --missing`, `say <text>`, `mics`, `check` (config valid, CUDA available, Ollama reachable or API key present, voiceprint present, IR codes per device). Shared `--config` (default `config.yaml`) and `--dry-run`. `python -m waifu` works via `__main__.py`.

### autostart (v1.1)

User story: the owner logs in to Windows and, without typing anything, Cyrene starts, loads her models, and says she is ready; closing her window stops her; she never runs twice.

- `single_instance.py` — `InstanceLock(path)`: context manager / `acquire() -> bool`, `release()`. Uses an OS byte-range lock on an open file (`msvcrt.locking` on Windows, `fcntl.flock` elsewhere) so a crashed or killed process never leaves a stale lock. Lock file `data/run.lock` (parent created). A second `acquire()` from another process returns False. `waifu run` takes it before loading anything, and `waifu enroll` and `waifu speaker-test` take it too (held while recording), so they never record while a running Cyrene also hears, and obeys, the owner. If taken, the command logs a WARNING, prints "Cyrene sudah berjalan (mungkin dari autostart). Tutup jendelanya dulu, atau jalankan 'waifu autostart status'." and exits 2.
- `autostart.py` — per-user Run key `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`, value name `Cyrene` (`RUN_VALUE`). `RunKey` protocol: `get(name) -> str | None`, `set(name, command)`, `delete(name) -> bool`; `WindowsRunKey` implements it with `winreg` (REG_SZ, only HKCU, only that key). `build_command(project_dir, waifu_exe, *, delay_s=15, comspec=None) -> str`: `<comspec> /c start "Cyrene" /min /d "<project_dir>" "<waifu_exe>" run --startup-delay <n> --announce --log-file logs\waifu.log`, where `<comspec>` is the `comspec` argument, else `%ComSpec%` (e.g. `C:\WINDOWS\system32\cmd.exe`), else `cmd.exe`, quoted when it contains whitespace (paths quoted for spaces; validated by parsing it back with `subprocess.list2cmdline`-compatible rules in tests). `enable(run_key, command)`, `disable(run_key) -> bool`, `status(run_key, expected_command) -> AutostartStatus(enabled, command, matches_expected)`.
- CLI:
  - `waifu autostart enable [--delay 15] [--force]` refuses (exit 2) when `speaker.enabled` and no voiceprint, or `config.yaml` is missing, unless `--force`; prints the command and how to undo it (`waifu autostart disable`; Task Manager → Startup apps lists the entry as "Windows Command Processor", cmd.exe's description, and a disable made there is invisible to `enable` and `status`). `project_dir` = current working directory resolved; `waifu_exe` = `<sys.prefix>\Scripts\waifu.exe` (must exist).
  - `waifu autostart disable` removes the value (ok if absent).
  - `waifu autostart status` prints enabled/disabled, the stored command, whether it matches what `enable` would write from the current folder and venv (keeping the `--startup-delay` already stored, so only a moved project or venv counts as stale), whether an instance is running (lock held), and the log path with its last 5 lines when present. The lock and the log are checked in the folder the stored command starts in (its `start /d` folder, when it exists; else the current folder). Run from another folder without a `config.yaml`, it says to run it from that project folder instead of calling the command stale.
  - `waifu run --startup-delay N` (default 0) sleeps N seconds first (logged); `--announce` speaks "<name> siap, Master." after everything is loaded. The announcement is not a reply: it leaves the follow-up window closed, so only the wake word starts a conversation.
  - `run` preloads models before printing/speaking that it is ready: `WhisperStt.preload()` and the speaker embedder (`SpeakerVerifier.preload()` → `EcapaEmbedder` load), so the first command is not delayed ~30 s.
  - Global `--log-file PATH`: also log to a rotating file (1 MB × 3, UTF-8, parent created) in addition to the console. Every error that ends a command (config error, missing package, unexpected exception) is logged at ERROR as well as printed, with the traceback only under `-v`, so a closed autostart window leaves its reason in the log.
- Never touched by tests: the real Run key and `reg.exe`/`schtasks` (guarded in `tests/conftest.py`), the real lock file outside `tmp_path`.

### anime voice (v1.2)

User story: everything Cyrene says, Indonesian and Japanese, comes out in one anime character voice (つくよみちゃん, trained locally with RVC from the free Tsukuyomi-chan corpus, ~11 min); if the voice converter is unavailable she still speaks with the plain edge-tts voice.

Voice rights: the corpus terms allow private use without restriction when neither the voice nor audio made from it is published. The model, corpus, and converted audio stay under `C:\AI` (outside the repo, never committed or redistributed). README tells the owner to credit "つくよみちゃんコーパス（CV.夢前黎）" and read the terms before publishing any audio.

Architecture: Applio (MIT, its own Python 3.12 env at `tts.rvc.applio_dir`) does the conversion in a long-lived local HTTP server so the model loads once; Cyrene (Python 3.14) talks to it over `127.0.0.1`.

- `tools/rvc_server.py` — runs under Applio's python (`tts.rvc.python_path`), stdlib `http.server` only plus Applio. `python tools/rvc_server.py --applio-dir D --model M.pth [--index I.index] --host 127.0.0.1 --port 9881`. Applio is imported lazily inside `load_applio_converter(applio_dir)` (adds it to `sys.path`, `os.chdir` into it because Applio resolves its asset paths relative to the CWD) so the module imports without Applio for tests. `make_handler(converter, model_name)` builds the request handler: `GET /health` → 200 JSON `{"ok": true, "model": ...}`; `POST /convert?pitch=&index_rate=&protect=` with a WAV body (≤ 20 MB, else 413) → 200 `audio/wav`; bad query/body → 400 JSON error; converter failure → 500 JSON error (logged); a body shorter than its Content-Length → 400; a socket timeout (30 s) keeps a stalled client from blocking the server. Converter contract: `convert(wav_bytes, *, pitch, index_rate, protect) -> wav_bytes`; the Applio implementation writes temp files and calls `VoiceConverter.convert_audio(..., f0_method="rmvpe", embedder_model="contentvec")`, warming up once at start with 1 s of quiet harmonic tone (digital silence trips a CUDA device assert in the pitch embedding, which killed the server on the owner RTX 5060 Ti); all-silent input is returned unchanged without calling Applio. Applio replaces "trained" with "added" anywhere in the index path and silently converts without an index when that path does not exist, so `load_applio_converter` refuses (ValueError, before importing Applio) an index whose rewritten path is missing, and keeps a legacy `trained_*.index` whose `added_*.index` exists. Binds only to the given host (default loopback). One request at a time (`HTTPServer`, not threading).
- `src/waifu/voice/rvc.py` — `RvcError`, and its subclass `RvcUnavailableError` (the server could not be reached or did not answer in time). `RvcClient(config: RvcConfig, *, http_post=None, http_get=None)`: `served_model() -> str | None` (the `model` of a `GET /health` reply `{"ok": true, "model": ...}`; None when nothing answers or what answers is not the RVC server), `convert(audio, sample_rate) -> (audio, sample_rate)` (WAV via soundfile, POST with the configured pitch/index_rate/protect, timeout 5 s + 0.5 × clip length, at most 30 s, decode; transport errors, including `http.client.HTTPException`, → `RvcUnavailableError`). The default transport bypasses any proxy. `require_loopback_host(host)`: `RvcError` unless `tts.rvc.host` is an IPv4 loopback address (the server has no password; `localhost` costs ~2 s per request on Windows). `require_served_model(config, served, base_url)`: `RvcError` (Indonesian, "stop the old server") unless the served model file name equals `tts.rvc.model`'s. `RvcServerProcess(config: RvcConfig, *, popen=subprocess.Popen, client=None, clock=time.monotonic, sleep=time.sleep, log_path=Path("logs/rvc_server.log"), lock_path=Path("data/rvc_server.lock"), server_script=None, job_factory=None)`: `ensure_running() -> None` checks the host, then takes the start lock (`InstanceLock` on `lock_path`; when another command holds it, waits up to `startup_timeout_s` for that command's server instead of spawning a second one). Holding it, it reuses a server on the port that serves the configured model (another model → `RvcError`), else checks `python_path`/`model`/`index`/`tools/rvc_server.py` exist (`RvcError` with an Indonesian hint), spawns it (cwd `applio_dir`, `CREATE_NO_WINDOW` when available, stdout/stderr appended to the log, environment plus `PYTHONIOENCODING=utf-8` and `PYTHONUNBUFFERED=1`), puts it in a job from `job_factory` (default `KillOnCloseJob` on Windows: a job object with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE` whose only handle Cyrene holds, so the OS kills the server, and the processes it started, however Cyrene ends, including a closed console window, which ends Python without running `finally`; a job that cannot be made or joined is logged as a warning, not fatal), polls `served_model()` until `startup_timeout_s` (process exit or timeout → `RvcError` naming the log). A server that answers after its own child exited is treated as reused, not owned. `stop()` terminates the child it started (never a server it merely reused) and closes its job; context manager. The repo path of `tools/rvc_server.py` is resolved from the package location.
- `voice/tts.py` — `SpeechRouter(engines, default_language, *, converter=None, clock=time.monotonic)`: after joining the runs, `converter.convert(audio, sr)` when set; an `RvcError`/`OSError`/timeout is logged once per failure streak and the unconverted audio is returned (she must never go silent because of the voice converter). After an unreachable converter (`RvcUnavailableError` or `OSError`), replies skip it for 60 s (`CONVERSION_RETRY_S`) and then try it again; an error from a server that answered (HTTP 500) causes no pause. `build_speech_router(config: TtsConfig, *, converter=None)`.
- CLI: `run`, `say`, and `chat --speak` start the server via `RvcServerProcess` when `tts.rvc.enabled` (inside the instance lock for `run`, before "ready"/announce, as part of preloading) and stop it on exit; `say --raw` skips conversion for an A/B comparison; `say` without `--raw` prints a one-line warning when `tts.rvc.model` is set but `tts.rvc.enabled` is false. `check` reports RVC: disabled, or each path present, a host that is not IPv4 loopback (✗, no probe), and whether a server answers on the port and with which model (✗ when it serves another model than `tts.rvc.model`; no spawning). `--dry-run` does not affect voice.
- `tests/conftest.py` refuses spawning `rvc_server.py` for real; tests use fake popen/http/converter/job and a start lock under `tmp_path`. ### avatar (v1.3)

User story: while Cyrene runs, a 3D anime girl stands on the owner's desktop (transparent, always on top, draggable). She breathes, blinks, and looks at the owner when idle, looks thoughtful while thinking, moves her mouth in sync with every spoken reply, and shows the reply's emotion on her face. Closing the mascot does not stop Cyrene.

Model rights: the official Tsukuyomi-chan 3D model "Type A" (VRM 0.x, UniVRM 0.62, © Rei Yumesaki, https://tyc.rei-yumesaki.net/material/avatar/3d-a/) allows personal use; software that ships it must credit "つくよみちゃん（© Rei Yumesaki）". The VRM stays under `C:\AI\avatars\` (never committed); the page always shows a small credit line. Its presets: visemes `a i u e o`, `joy angry sorrow fun neutral`, `blink blink_l blink_r`, look `up down left right`, custom `Surprised`; no animations (pose and idle motion are procedural).

Architecture: Cyrene runs a loopback HTTP server (`avatar.host`/`avatar.port`, default 127.0.0.1:9882) that serves the viewer page, the VRM, and a Server-Sent Events stream of avatar events. The page renders with three.js 0.186 + @pixiv/three-vrm 3.5 (vendored, MIT, `src/waifu/avatar/web/vendor/`, see VENDOR.md, mapped by an import map). The mascot is an Electron 44 shell (`avatar-app/`) loading that page in a transparent frameless window; `window: app` uses an Edge app window instead; `window: none` only serves the page.

Event protocol (SSE `data:` lines, one JSON object each; `type` decides the rest):
- `{"type":"hello","model":"/model.vrm","name":"Cyrene","framing":"full","credit":"つくよみちゃん（© Rei Yumesaki）"}` — first message on every connection, followed by the last `state` and, while a reply is still playing, its `speak` event with `elapsed`.
- `{"type":"state","state":"idle"|"listening"|"thinking"|"speaking","followup_s":8}` — `followup_s` only with `listening` (after a reply, while the follow-up window is open; the page returns to idle by itself after it). With `assistant.followup_seconds: 0` there is no window, so a reply ends in `idle`; the page also treats `followup_s` ≤ 0 as idle at once and a missing one as listening until the next state.
- `{"type":"speak","emotion":"happy","fps":60,"duration":3.42,"visemes":[[aa,ih,ou,ee,oh],...]}` — published immediately before playback starts; weights 0..1 rounded to 2 decimals; the page plays the track from the moment it receives it and returns to a neutral mouth after `duration`. A viewer that subscribes while it plays gets it replayed with `"elapsed":0.75` (s already played, 3 decimals); the page starts the track that much earlier.
- `{"type":"emotion","emotion":"happy","hold_s":4}`.
Emotion names: `neutral happy sad angry surprised relaxed` (the page maps them to VRM expressions `neutral happy sad angry Surprised relaxed`; three-vrm maps the VRM 0.x presets joy/sorrow/fun to happy/sad/relaxed).

Python (`src/waifu/avatar/`):
- `emotion.py` — `EMOTIONS` (the six names). `split_emotion(text) -> tuple[str, str]`: a leading tag in square brackets (Indonesian `senang sedih marah kaget santai netral` or the English names, case-insensitive, optional spaces; the full-width brackets `［ ］` and `【 】` of Japanese text count too) selects the emotion and is removed; any other such emotion tag anywhere is removed too (it must never be spoken or printed); text without a tag → `("neutral", text)`; other bracketed text like `[1]` is left alone. `config/persona.md` asks the model to start every text it writes, also the text after a tool call (only the last one is spoken), with one of the Indonesian tags.
- `lipsync.py` — `viseme_track(audio, sample_rate, fps=60) -> list[tuple[float, float, float, float, float]]` (aa, ih, ou, ee, oh), one frame per 1/fps s (`ceil(duration*fps)` frames). Openness from frame RMS in dBFS mapped linearly from −50 dB (closed) to −15 dB (fully open), smoothed with a fast attack and a slower release; vowel shape from the frame's spectral centroid (low → ou/oh, mid → aa, high → ee/ih) blended with a baseline of aa so the mouth always opens; a frame's weights sum to at most its openness. Pure numpy.
- `bus.py` — `AvatarBus(name="Cyrene", framing="full", *, clock=time.monotonic)`: thread-safe fan-out. `subscribe() -> Subscription` (bounded queue of 64, the oldest event dropped when full, never blocks the publisher; the first items are hello + last state, then the last speak event with `elapsed` while `elapsed < duration` and no state other than `speaking` came after it), `unsubscribe(sub)`, `wait_for_viewer(timeout) -> bool` (whether a subscriber exists, waiting up to `timeout` s for one; False at once after `close()`), `publish(event)`, and helpers `state(name, followup_s=None)`, `speak(audio, sample_rate, emotion)` (builds the speak event with `viseme_track`), `emotion(name, hold_s=4)`, `close()` (wakes every subscriber so SSE handlers return).
- `server.py` — `AvatarError`. `AvatarServer(config: AvatarConfig, bus, *, web_root=<package>/avatar/web)`: `ThreadingHTTPServer` (daemon threads) bound to the configured host/port; `start()` serves in a daemon thread, `stop()` closes the bus subscriptions, shuts down, and closes the socket; `url` (`http://host:port/`); context manager. Every request whose `Host` is not `<host>:<port>` of the server or `localhost:<port>` gets 403 before routing (DNS rebinding; 421 before v1.5). Routes (GET only, others 405; v1.5 adds `POST /interact` and the Live2D routes, see "Live2D and interactions (v1.5)"): `/` → `index.html`; `/events` → SSE (`text/event-stream`, `Cache-Control: no-cache`, `retry: 2000`, a `: ping` comment every 15 s, ends cleanly on client disconnect); `/model.vrm` → the configured `avatar.model` file (404 when missing; `model/gltf-binary`); any other path → a file under `web_root` (the resolved path must stay inside `web_root`, else 404; no directory listing; content types for .html .js .mjs .css .json .png .svg .md; `Cache-Control: no-store` for .html). A port in use → `AvatarError` with an Indonesian hint.
- `window.py` — `AvatarWindow(config, url, *, popen=subprocess.Popen, edge_path=None, job_factory=None, project_root=<repo root>)`: `open()` for `mascot` runs `<electron_dir>/node_modules/electron/dist/electron.exe <electron_dir> --url=<url>?mode=mascot --width=W --height=H --corner=C --always-on-top=1|0` (`electron_dir` relative to the project root; a missing exe → `AvatarError` telling the owner to run `npm install` and `node node_modules/electron/install.js` in `avatar-app`); for `app` runs Edge (`edge_path`, else `%ProgramFiles(x86)%` / `%ProgramFiles%` `Microsoft\Edge\Application\msedge.exe`) with `--app=<url>?mode=app --window-size=W,H --user-data-dir=<project>/data/avatar-edge-profile` (a separate profile so the window is its own process that can be closed); `none` does nothing. The child goes into a kill-on-close job (reuse `waifu.voice.rvc.KillOnCloseJob`; a failure is only logged) so it dies with Cyrene. `close()` terminates only what it started; idempotent; context manager; never raises.
- `app.py` integration — `Assistant(..., avatar: AvatarBus | None = None)`: `state("thinking")` once the gate accepts a command; replies go through `split_reply` (`split_emotion`, and a reply that was only a tag becomes `Sudah, Master.`, or a short apology when a tool failed or none ran) before speaking (also without an avatar, so tags are never spoken and she never goes silent); right before `player.play` → `avatar.speak(audio, sr, emotion)`; after speaking → `state("listening", followup_s=config.assistant.followup_seconds)`, or `state("idle")` when that is 0; a bare wake-word acknowledgement uses `happy`; avatar errors are logged and never stop the voice loop. `handle_text` (chat) returns the reply with the tag removed.
- CLI — when `avatar.enabled`: `run` (inside the lock, during preload, before "ready"), `say`, and `chat --speak` start `AvatarServer` + `AvatarWindow` and close them on exit; a failure prints an Indonesian warning and continues without the avatar. A speak event reaches only viewers already connected, so `say` (after synthesis) and `run --announce` (before the greeting) wait up to 5 s for the page to subscribe (`wait_for_viewer`), unless `avatar.window` is `none`; `chat --speak` and replies in `run` do not wait. New `waifu avatar [--demo]`: start server and window, print the URL, keep running until Ctrl+C; `--demo` cycles the six emotions and the states every few seconds so the owner can check the model without talking. `check` reports: avatar disabled, or the VRM exists, the window program exists (Electron exe for mascot, Edge for app), and whether the port is free (no spawning).

Web (`src/waifu/avatar/web/`):

### notify (v1.4)

### long-term memory (v1.6)

User stories (the owner talks to Cyrene every day; today she forgets everything when a session ends):

1. "Cyrene, ingat ya, aku alergi udang." → she saves it and confirms in one sentence. Days later, "Cyrene, enaknya masak apa?" → she avoids shrimp without being reminded.
2. She also saves on her own the lasting things the owner mentions in passing: likes and dislikes, plans with a date ("Jumat ada ujian"), people and pets, routines, favourite games and characters. Small talk, device commands, and anything already saved are not saved.
3. "Cyrene, apa saja yang kamu ingat tentang aku?" → a short spoken summary, not a list read out.
4. "Cyrene, lupakan soal udang." → she deletes that note. When a fact changes ("sekarang aku sudah tidak kerja di sana") she updates the old note instead of keeping two that contradict.
5. Secrets are never kept: a note that looks like a password, PIN, OTP, token, cookie, API key, or card number is refused in code, whatever the model asks for.
6. The owner can read, add, delete, and wipe the notes from the terminal (`waifu memory`), or edit `data/memory.json` by hand.

Non-goals: a summary of every conversation (only facts the model chose to save), embeddings or semantic search (the whole list fits in the prompt), syncing between PCs, memories per person (there is one owner).

Privacy: the notes live only in `data/memory.json` on this PC (`data/` is gitignored and never committed). With the Claude backend they are sent to the Claude API as part of the system prompt of every session, like the rest of the conversation; with Ollama they stay local. README says so.

Config `memory` (committed with its tests before the parallel tasks): `enabled` (default true), `path` (default `data/memory.json`), `max_facts` (default 100, 1-500), `max_chars` (default 200 characters per note, 20-1000).

`memory.py`:
- `Fact` (frozen dataclass): `id: str` (`"m1"`, `"m2"`, … never reused), `text: str`, `created: datetime`, `updated: datetime` (local time; minute precision is enough).
- `MemoryError(Exception)`: its message is Indonesian and safe to show or speak.
- `looks_secret(text) -> bool`: true when the text names a secret, contains a run of 20 or more characters from `[A-Za-z0-9_\-+/=]` that has both letters and digits, or contains 13-19 digits that pass the Luhn check, written together or in groups separated by single spaces or dashes (any stretch of neighbouring whole groups counts, so a card number said with its expiry or CVV, `4111 1111 1111 1111 12/28`, is caught; a group is never split). A secret is named by these case-insensitive words or phrases (the words of a phrase joined by spaces, `_`, `-`, or nothing), as whole words except that the Indonesian suffixes `-nya`, `-ku`, `-mu` and a number may follow right away (`passwordnya`, `PINnya`, `PIN1234`): `password` and its short forms `passwd`, `pw`, `pwd`, `passcode`, `kata sandi`, `sandi` with one of those suffixes or before an account (`wifi`, `email`, `akun`, `hp`, `laptop`, `atm`, `bank`; a bare `sandi` is also a name or a code like sandi Morse), `pin` except before `lokasi`, `koleksi`, `genshin`, `honkai`, `hsr`, `zzz` (a map pin or a badge), `otp`, `cvv`, `api key`, `token` except `token listrik` and `token PLN` (prepaid electricity), `seed phrase`. A bare `cookie` (a biscuit, Cookie Run) is not one; a cookie's value is caught as a long mixed token.
- `MemoryStore(path, *, max_facts=100, max_chars=200, now=datetime.now)`:
  - `facts() -> list[Fact]` (oldest first), `add(text) -> Fact`, `replace(fact_id, text) -> Fact` (keeps the id and `created`, new text and `updated`), `forget(fact_id) -> Fact` (the removed note), `clear() -> int` (how many were removed).
  - Text is stripped and its whitespace (newlines included) collapsed to single spaces. `MemoryError` for: empty text, text longer than `max_chars`, `looks_secret`, an unknown id, and `add` when `max_facts` notes exist (the message says to combine or delete old notes first). Adding a text equal to an existing note (case-insensitive) returns that note unchanged.
  - Every call re-reads the file, so a running Cyrene sees what `waifu memory` changed in another process; a `threading.Lock` serialises calls within one process; between processes the last writer wins (documented).
  - File: UTF-8 JSON `{"version": 1, "next_id": <int>, "facts": [{"id", "text", "created", "updated"}]}` (ISO 8601 times), written atomically (a temp file in the same folder, then `os.replace`); the folder is created on the first write. A missing file is an empty memory and reading never creates it. A file that is not valid JSON or not this shape is renamed to `<name>.corrupt-<YYYYmmdd-HHMMSS>`, logged as an error, and the memory starts empty: the owner's notes are never overwritten.
- `memory_prompt_section(facts) -> str`: the system-prompt section. With notes: `Ingatanmu tentang Master (catatan dari obrolan sebelumnya, tersimpan di PC ini):` then one line per note, `- m3 (12-10-2026): Master alergi udang.` (the date is `updated`; no square brackets, which the persona reserves for the emotion tag). Without notes: `Ingatanmu tentang Master: belum ada catatan.` Both end with the line `Pakai ingatan ini secara alami kalau relevan; jangan membacakan daftarnya kecuali Master memintanya. Simpan hal baru yang penting dengan tool remember, perbarui catatan yang berubah dengan replaces, dan hapus dengan forget kalau Master memintanya.`

`brain/memory_tools.py` — `MemoryTools(store)`, a `ToolProvider` with two strict tools (descriptions in English, like the other tools):
- `remember {text: string, replaces?: string}`: saves one note, or replaces note `replaces`. The description says what to save (lasting facts about Master and anything Master asks to remember, in Indonesian, in the third person, "Master …", one fact per call, with the date for plans, at most `max_chars` characters), what not to save (small talk, device commands, notes already in the list, and secrets: passwords, PINs, OTPs, tokens, cookies, card numbers), and to pass `replaces` with the old note's id when a fact changed. Result `{"ok": true, "id": "m4", "message": "Tersimpan."}` (`"Diperbarui."` for a replace); a `MemoryError` becomes `{"ok": false, "message": <its text>}` with `is_error` true.
- `forget {id: string}`: deletes one note; result `{"ok": true, "message": "Dihapus: <text>"}`; an unknown id is an error result.
- Invalid arguments (not an object, unknown keys, missing or empty strings) are error results; `run` never raises.
- `changed_memory(tool_calls) -> bool`: whether one of a turn's `ToolCallRecord`s is a successful `remember` or `forget` (see Brains).

Brains (`brain/claude.py`, `brain/ollama_brain.py`, `brain/factory.py`):
- `system_prompt` may be a string or a zero-argument callable. A callable is called once at the start of every session, in both brains when `respond` begins with an empty history (after construction, `reset`, an idle or turn-cap reset, and a rolled-back first turn; never while the brain is built, which `waifu run` does at login), and the result stays fixed for that session. Within a session the system prompt and the tools never change (preserved thinking and the prompt cache need a byte-identical prefix); a note saved mid-session is already in the conversation as a tool call, and the next session's prompt lists it. A turn rolled back after a successful `remember` or `forget` (an API error or a refusal later in that turn) would leave the change in neither the prompt nor the history, so it ends the session instead of truncating it: the next turn starts a new session whose prompt lists the notes as they are (`memory_tools.changed_memory(tool_calls)`). Tools stay fixed for the brain's lifetime.
- `build_brain(config, registry, *, persona_text=None, providers=(), memory_section=None)`: with `memory_section` (a zero-argument callable returning the section), the system prompt becomes a callable: the base prompt (persona, devices, time note; unchanged) followed by a blank line and `memory_section()`. If `memory_section()` raises, the error is logged and the section reads `Ingatanmu tentang Master tidak bisa dibaca saat ini.`, so the turn still works. The memory section comes last, so the persona and device prefix stays cacheable across sessions.

CLI (`cli.py`):
- `run` and `chat`: when `memory.enabled`, one `MemoryStore` from the config; `MemoryTools(store)` joins the providers (after the game tools) and `memory_section=lambda: memory_prompt_section(store.facts())` goes to `build_brain`. With `--dry-run` the real memory is used too (dry-run only fakes the devices).
- `waifu memory list` (each note as `m3  12-10-2026  Master alergi udang.`, or `Belum ada catatan.`), `waifu memory add <text…>`, `waifu memory forget <id>`, `waifu memory clear` (without `--yes` it only says how many notes would be deleted and how to confirm; with `--yes` it deletes them). Errors print `✗ <message>` and exit 1. These work while `memory.enabled` is false too (they manage the file).
- `check`: `✓ Ingatan: <n> catatan (<path>)`, or `! Ingatan mati (memory.enabled: false)`; a corrupt file shows the rename that happened.

Safety: tests never read or write the repository's `data/memory.json` (every test uses `tmp_path`; CLI tests point `memory.path` into it or turn memory off); no test calls Claude or Ollama.

### schedules, reminders, and routines (v1.7)

User stories:

1. "Cyrene, ingatkan aku jam 3 sore minum obat." → at 15:00 she says it by herself ("Master, sudah jam tiga, waktunya minum obat!") and the same text reaches the phone when notifications are on. "10 menit lagi ingatkan aku angkat jemuran" works the same way (the model turns relative times into a clock time; it knows the current time from the turn stamp).
2. "Cyrene, matikan AC jam 2 pagi." → at 02:00 the AC gets the command without a word spoken (the owner may be asleep); only a failure is announced and pushed.
3. "Cyrene, setiap hari jam 7 pagi bangunkan aku." / "tiap hari kerja" / "tiap akhir pekan" → repeating entries.
4. "Cyrene, ada jadwal apa saja?" → a short spoken summary; "batalkan pengingat obat" → she cancels it.
5. "Cyrene, mode tidur." → runs the owner's routine "tidur" from config.yaml (for example: lights off, AC to 26). Routines can be scheduled too ("jalankan mode tidur jam 11 malam").
6. Schedules fire only while `waifu run` is on (the PC is on); the README says so.

Non-goals: calendars or cloud sync, alarms with snooze or a ringtone, schedules that turn the PC itself off, restart it, or put it to sleep (a `pc` device is refused in schedules and routines; the voice command with its confirmation stays the only way; a plug that feeds the PC, marked `powers_pc: true` on its device like the example's `colokan_pc`, is guarded the same way, since switching it off while Windows runs cuts the PC's power), conditions ("if it is hot"), routines written by the model (only the owner writes them, in config.yaml).

Config (committed with its tests before the parallel tasks):
- `schedule`: `enabled` (default true), `path` (default `data/schedule.json`), `max_entries` (default 50, 1-200), `late_grace_minutes` (default 30, 0-720): how late an entry may still fire after the PC was off or Cyrene stopped.
- `routines`: a mapping of routine name (slug `^[a-z0-9_]+$`) → `{description: str (Indonesian, optional), steps: [{device: id, command: str, value?: int}]}`, 1-20 steps each. Validated against `devices`: the device id must exist, must not be of type `pc`, and must not be marked `powers_pc`. `DeviceConfig.powers_pc` (default false; only for `tuya_plug`, and `mock` in tests) marks the plug that feeds the PC. `DeviceRegistry(devices, *, pc_power_ids=())` gains `powers_pc(device_id) -> bool` (the PC itself or a marked plug; `build_registry` passes the marks, dry runs too); routines, the scheduler, and the schedule tools refuse whatever `powers_pc` names, and the device line in the prompt tells the model that switching a marked plug off turns the PC off, so the persona's confirmation rule covers it. Command validity is checked by `waifu check` (it needs the registry).

`schedule.py` (pure, no threads):
- `Entry` (frozen dataclass): `id: str` (`"j1"`, `"j2"`, … never reused), `at: datetime` (local, minute precision; the next time it fires), `repeat: Literal["none", "daily", "weekdays", "weekends"]`, `action: Reminder | DeviceAction | RoutineAction`, `created: datetime`. `Reminder(text)`, `DeviceAction(device, command, value: int | None)`, `RoutineAction(name)`.
- `ScheduleError(Exception)`: Indonesian message, safe to speak.
- `parse_local_time(text) -> datetime`: exactly `YYYY-MM-DD HH:MM`, else `ScheduleError`.
- `next_occurrence(at, repeat, after) -> datetime | None`: for `none` None; otherwise the first time on the repeat's days (`weekdays` Monday-Friday, `weekends` Saturday-Sunday) with the same clock time that is later than `after`.
- `ScheduleStore(path, *, max_entries=50, now=datetime.now)`: `entries() -> list[Entry]` (soonest first), `add(at, repeat, action) -> Entry`, `cancel(entry_id) -> Entry`, `fired(entry_id, at) -> Entry | None` (removes a one-shot entry, or moves a repeating one to its next occurrence after both `at` and now; returns the updated entry or None), `skipped(entry_id, at, earliest) -> Entry | None` (the same for an occurrence missed as too late, except that a repeating entry moves to its first occurrence at or after `earliest`, which may already be due), `clear() -> int`. `add` refuses (ScheduleError): a time before the current minute (the current minute itself is accepted and fires at the next tick: "in one minute" said just before the minute changes reaches the store after it did), more than 366 days ahead, a full store, a reminder text that is empty or over 200 characters, an unknown repeat. Same file rules as `memory.py`: re-read per call, lock within the process, atomic `os.replace`, never created by reading, a corrupt file renamed `<name>.corrupt-<stamp>` and never overwritten. JSON: `{"version": 1, "next_id": n, "entries": [{"id", "at", "repeat", "action": {"type": "reminder", "text"} | {"type": "device", "device", "command", "value"} | {"type": "routine", "name"}, "created"}]}`.
- `due(entries, now, grace) -> tuple[list[Entry], list[Entry]]`: (entries to fire now: `at <= now` and `now - at <= grace`), (entries missed by more than `grace`: skipped).

`routines.py`: `run_routine(registry, routine: RoutineConfig) -> list[DeviceResult]` runs every step in order through `registry.execute`, continuing after a failed step, and refuses at run time too a step whose device `registry.powers_pc` names (the PC or a plug marked `powers_pc`), with `pc_power_refusal(registry, device_id, where) -> str | None` (an Indonesian reason; `where` is "jadwal" or "rutinitas"; shared with the scheduler); `describe_routine(name, routine) -> str` (one Indonesian line for tool descriptions and `waifu routine list`, e.g. `tidur: Mode tidur (lampu_kamar off, ac temp 26)`); `routine_problems(registry, routine) -> list[str]` (one Indonesian line per step whose device is missing, powers the PC (`registry.powers_pc`), or has no such command per `devices.ir_device.resolve_command (the rule registry.execute uses)`; empty when the routine is fine).

`scheduler.py` — `Scheduler(store, *, registry, routines, announce, notifier, grace_minutes, now=..., tick_seconds=15)`, a daemon thread like `GachaWatcher` (`start`, `stop`, context manager, `tick_once()` for tests):
- Each tick handles one entry at a time, soonest first, each picked from a fresh read of the store and a fresh `now` (so an entry cancelled while an earlier one ran never runs, and one that came due meanwhile runs in the same tick). `earliest` = the earlier of (the tick's starting minute − grace) and (the minute `tick_seconds` before the tick started); an entry older than `earliest` is skipped, a due one fires. For every entry to fire: a reminder → `announce(text, "happy")` and `notifier.send(title, text)`; a device action → `registry.execute` (refusing, through `pc_power_refusal`, anything `registry.powers_pc` names, again at run time), silent on success, on failure announce and push `Master, jadwal <device> <command> jam HH.MM gagal: <message>`; a routine → `run_routine`, silent on success, a failure announced and pushed the same way (naming the failed steps). Then `store.fired(entry.id, entry.at)`. Skipped (too late) entries: `store.skipped(entry.id, entry.at, earliest)`: one-shot ones are removed and logged, repeating ones move to their first occurrence still within the grace (after days away, today's still fires); a skipped reminder is pushed to the phone as `Terlewat (HH.MM): <text>` (`Terlewat (DD-MM-YYYY HH.MM): <text>` when it was not today's); the skipped one-shot reminders of a tick are also told once, together, with emotion `sad`: `Master, ada pengingat yang terlewat jam HH.MM: <text>` for one (`tanggal D jam HH.MM` when not today's, with the Indonesian month name after D when the month or year differs from today's and the year after that when the year differs), `Master, ada N pengingat yang terlewat. Jam HH.MM: <text> Jam ...` for several. A skipped repeating reminder is only pushed (it comes again).
- A failure inside one entry is logged and never stops the thread or the other entries; `announce` and `notifier` may be None.

`brain/schedule_tools.py` — `ScheduleTools(store, *, registry, routines)`, a `ToolProvider` with strict tools (English descriptions):
- `schedule {at: string "YYYY-MM-DD HH:MM" local time, repeat?: enum none|daily|weekdays|weekends, reminder?: string, device?: string, command?: string, value?: integer, routine?: string}`: exactly one action (a reminder text; or device + command [+ value], validated when it is scheduled with `devices.ir_device.resolve_command (the rule registry.execute uses)` against the device's commands, a device `registry.powers_pc` names (the PC or a marked plug) refused and left out of the `device` enum; or a routine name from config). The description explains turning relative times into a clock time from the turn's time stamp, writing the reminder text as what she should say to Master, and that a past time today usually means tomorrow. Result `{"ok": true, "id": "j3", "at": "2026-10-13 15:00", "repeat": "none"}`.
- `list_schedules {}` → the entries with id, local time, repeat, and a short description of the action.
- `cancel_schedule {id: string}`.
- `run_routine {name: enum[routine names]}` (only when routines exist) → the steps' results; its description lists each routine with `describe_routine`.
- Errors are `is_error` results with Indonesian messages; `run` never raises.

CLI:
- `run`: when `schedule.enabled`, the store, `ScheduleTools` (after the memory tools), and a `Scheduler` started inside the voice loop's lifetime with `assistant.announce` and the notifier; `chat`: the tools and a scheduler whose announce prints `Cyrene: <text>`, but only when no `waifu run` holds the run lock (otherwise that one fires the schedule and chat prints a note that it does). With `--dry-run` (both), the session gets an empty schedule of its own in a temporary folder, deleted when it ends: `schedule.path` is never read or written, so simulated devices never use up real entries and entries made in a dry run never run on real devices.
- `waifu schedule list | cancel <id> | clear [--yes]`, `waifu routine list | run <name>`; `check` reports the schedule file (`✓ Jadwal: <n> entri`) and every routine (✓, or ✗ naming an unknown command per step).
- README (Indonesian): how to ask for reminders, device schedules, and routines; writing routines in config.yaml (with a `tidur` example); that schedules fire only while `waifu run` is on and what happens to late ones; that the PC itself is never scheduled.

Safety: tests never touch the repository's `data/schedule.json`, never run real devices (mock registry), never sleep for real (injected clock, `tick_once`), and never call an LLM.

### PC media and apps (v1.8)

User stories (the owner plays games and listens to music on this PC):

1. "Cyrene, pause musiknya." / "lagu berikutnya" / "kecilkan volume" / "kecilkan volume 20 persen" / "volume 30" / "mute" → the Windows media and volume keys, whatever player is open (Spotify, YouTube in the browser, a game). Except while a program running as administrator has focus (HoYoverse games and launchers, other anti-cheat games): Windows drops injected keys silently (UIPI), with no error, so replies say which key was pressed, never what happened, and the README says so up front.
2. "Cyrene, buka Genshin." / "buka Spotify" → starts an app or game the owner listed in config.yaml: a program, a shortcut, or a launcher URL such as `steam://rungameid/...`.
3. Both are ordinary devices, so they work in schedules and routines too: "mode tidur" can stop the music and turn the volume down; "jam 7 pagi buka Spotify" works.
4. Nothing outside the owner's list is ever started, and nothing is ever closed or killed.

Non-goals: closing apps or killing processes, typing or clicking inside apps, per-app volume, choosing a song or playlist, anything that plays a game (macros break HoYoverse's terms), reading the current volume.

Both are devices, so `control_device`, `list_devices`, schedules, routines, `waifu device`, `waifu devices`, and dry runs (mock copies keep the kind and commands) need no new tools.

Config (committed with its tests before the parallel tasks): `DeviceConfig.type` gains `media` and `apps`. `DeviceConfig.apps: dict[str, str] | None` maps an app slug (`^[a-z0-9_]+$`) to its target; it is required for `type: apps` (1-30 apps) and refused for every other type. A target is either a URL whose scheme is `steam` or `com.epicgames.launcher`, or an absolute Windows path ending in `.exe`, `.lnk`, or `.url` (case-insensitive); anything else (`.bat`, `.cmd`, `.ps1`, `.vbs`, a relative path, another scheme) is a config error. Whether the file exists is checked by `waifu check` and at run time, not at load, so a moved game never stops Cyrene from starting. `commands` is ignored by both types (their commands are fixed or come from `apps`).

`devices/media.py` — `MediaKeys(device_id, name, aliases, *, press=press_keys)`, kind `media`:
- `press_keys(keys: Sequence[int]) -> None`: the real sender, `user32.SendInput` with one key-down and one key-up `INPUT` (type `INPUT_KEYBOARD`, `KEYBDINPUT.wVk`, `KEYEVENTF_KEYUP` for the release) per virtual key, through `ctypes.WinDLL("user32", use_last_error=True)` with full `argtypes`/`restype`; a short send (fewer events than given) raises `OSError` with `ctypes.get_last_error()`, which `MediaKeys` logs and turns into the `DeviceError` `Windows menolak tombol medianya, jadi perintahnya tidak sampai.`
- Commands and keys: `play_pause` (VK_MEDIA_PLAY_PAUSE 0xB3), `next` (0xB0), `previous` (0xB1), `stop` (0xB2), `mute` (VK_VOLUME_MUTE 0xAD, a toggle), `volume_up` (0xAF) and `volume_down` (0xAE): every volume `value` is a percentage, as the owner says it, so these take 1-100 (default 10 without a value) and press `max(1, value // 2)` keys of 2 % each; `volume` with `value` 0-100: 50 × volume down, then `value // 2` × volume up (Windows has no key for a level; no new dependency). A value outside its range is a `DeviceError`; `volume` without a value too. State: `{"last": <command>}`. Messages are Indonesian and say which key was pressed, never the outcome, which Windows does not report ("Tombol volume sudah ditekan untuk mengatur ke sekitar 30%.").
- Value ranges fixed by the kind live in `devices/registry.KIND_VALUE_RANGES`: `("light", "brightness")` 1-100 and `("media", "volume")` 0-100, both required; `("media", "volume_up")` and `("media", "volume_down")` 1-100, optional. `registry.value_problem` refuses a value outside its range, or a missing required one, with one Indonesian message, in `DeviceRegistry.execute`, in `ScheduleTools` when an entry is made, and in `routine_problems`, so a bad value never waits to fail at a scheduled time. `brain/tools.describe_commands` shows the ranges, the `control_device` description says brightness and volume values are percentages, and the `media` device line notes that `play_pause` and `mute` toggle (use `stop` and `volume` in schedules).
- Schedules: `ScheduleTools` refuses `play_pause` and `mute` on a `media` device with an Indonesian hint to schedule `stop` or `volume`: both toggle, and a device schedule runs silently, so they could restart music Master paused, or unmute the PC, at night. Its description says the same. Routines are left to the owner, who writes them knowingly; the README tells them to use `stop` and a low `volume`.

`devices/apps.py` — `AppLauncher(device_id, name, aliases, apps: Mapping[str, str], *, start=_shell_open, exists=os.path.exists)`, kind `apps`:
- Commands `open_<slug>` for each app, in config order; like the registry and the dry-run mock, `execute` resolves a command and value with `resolve_command` (`open_gta` + 5 is `open_gta_5`). `execute` starts the target with `start(target, folder)`, by default `os.startfile(target, cwd=folder)` (Windows' own "open": it follows shortcuts and launcher URLs and never waits for the program, but does wait until an administrator prompt it raises is answered, by voice or on the scheduler thread). A `.exe` target starts in its own folder, as from Explorer (otherwise it would inherit Cyrene's working folder, the project); shortcuts and URLs get `None` (a shortcut has its own "Start in"). A path target whose file is missing, or a failed start (`OSError`), is a `DeviceError` with an Indonesian message naming the app; a refused administrator prompt (`winerror` 1223, `ERROR_CANCELLED`) says so instead of suggesting a missing install. URL targets are not checked for existence. State: `{"last_opened": <slug>}`. Message: `"<slug> dibuka."` (or a friendlier Indonesian line).

Registry: `build_registry` builds `MediaKeys` for `media` and `AppLauncher` for `apps`.

CLI and docs: `waifu check` reports each app (✓ file found / ✗ file missing / URL, not checked); a `.url` shortcut's `URL=` (an INI file, read, never opened) is ✗ unless it is a launcher URL; `.lnk` targets are not read. README (Indonesian) section "Musik, volume, dan aplikasi PC" with voice examples, the config (`media` device with the aliases `volume` and `suara`; `apps` with Start Menu shortcut paths, how to find a game's shortcut or Steam URL), that routines should use `stop` (not `play_pause`, which may start playback), that schedules refuse the toggles, that the volume keys also set Cyrene's own voice (so `volume 0` silences her spoken reminders), that keys do not reach a game running as administrator, that a shortcut opens whatever it points to, that Cyrene and her schedules wait on an administrator prompt, and that nothing is ever closed. `config.example.yaml` gets commented `media` and `apps` devices.

Safety: tests never press real keys or start real programs. `tests/conftest.py` is strengthened (never weakened): `os.startfile` refused, and `SendInput` and `keybd_event` refused on any `user32` loaded through `ctypes.WinDLL` or `ctypes.windll`; `tests/test_safety_guard.py` covers both. The real senders are module-level defaults injected into the devices, so tests pass fakes.

### confirmation in code (v1.9)

User story: "Cyrene, matikan komputer." → she asks "Komputer mau kumatikan sekarang, Master? Jawab iya kalau jadi."; it runs only when the owner's next words are a plain yes ("iya", "boleh", "iya, matikan"). Until v1.9 that was only a persona rule: a model that skipped the question, or misheard, could turn the PC off at once, and the plug that feeds it cuts the power with no delay at all. Now the code enforces it with the owner's own words, and the code itself asks the question, so the owner always hears what a yes would run.

What needs confirmation (`needs_confirmation(registry, device_id, command, value) -> bool`, on the command `resolve_command` picks): on a device of kind `pc`, `shutdown`, `restart`, and `sleep` (not `wake` or `cancel_shutdown`); on any other device `registry.powers_pc` names (a plug marked `powers_pc`), `off` and `toggle` (not `on`). Nothing else.

`brain/confirm.py`:
- `is_yes(text, names=()) -> bool`: a plain yes. The owner's words (NFKC, lowercased, split on anything that is not a letter or digit in any script, so Japanese kana/kanji runs are words), leaving out `master` and the words of `names` (her name and wake words), must not be empty, must start with an affirmative word (`ya`, `iya`, `iyaa`, `yes`, `yup`, `yap`, `boleh`, `oke`, `okey`, `ok`, `okay`, `lanjut`, `lanjutkan`, `betul`, `benar`, `silakan`, `setuju`, `gas`, `yakin`, `yaudah`, `siap`, `sip`, `yoi`, `はい`, `うん`), and must hold nothing but affirmative words and order words, which only repeat or soften the order (`aja`, `saja`, `deh`, `dong`, `sekarang`, `langsung`, `udah`, `sudah`, `matikan`, `matiin`, `shutdown`, `restart`, `sleep`, `tidurkan`, `komputer`, `komputernya`, `pc`, `nya`, `colokan`, `colokannya`, `どうぞ`, `お願いします`). Text with a question mark is never a yes. "Iya, matikan", "Cyrene, boleh", and "ya udah, matiin aja" are yes. Everything else is not, including a "ya" in thanks, another request, or a reason to wait ("oke makasih ya", "nyalakan lampu kamar ya", "iya ntar", "bentar ya, aku save dulu", "ya kali, aku lagi main game", "ya udah, lampunya aja"), any refusal ("eh jangan, tunggu", "ya gausah"), doubt ("kurang yakin"), and questions ("iya?"). The list is closed on purpose: a false no only costs one more question, a false yes turns the PC off.
- `ConfirmationGate(*, clock=time.monotonic, window_s=60, names=())`:
  - `begin_turn(user_text)`: called by the brain at the start of every `respond`, with the owner's words as heard. Reads the clock (the time her words arrive), remembers whether they are a yes (`is_yes(user_text, names)`), makes the previous turn's request the one this turn may answer, and lets any older request expire.
  - `check(registry, device_id, command, value) -> str | None`: None when the call may run now; otherwise the Indonesian message for the model. A command that `needs_confirmation` runs only when it is the previous turn's request (same device, resolved command, and value), this turn is a yes, and this turn began at most `window_s` seconds after that request was refused; the request is then used up. Otherwise the call is refused, and the first call refused in a turn becomes that turn's request: its message says it was not run, quotes the question the owner will hear after the reply, tells the model not to ask it again, and to call the same command again only after the owner answers yes. A different call refused later in the same turn is not asked about: its message says only one such command is asked per turn and the owner can ask for it again later (so "shut the PC down and cut its plug" needs two separate yeses, never one). A yes in the same turn as the request, the model's own words, or a yes more than one turn later never count.
  - `with_question(reply) -> str`: the reply followed by the question of this turn's request, if there is one (the question alone for an empty reply). The question names the device and the action and, for a plug, warns that the PC's power may be cut at once: `Komputer mau kumatikan sekarang, Master? Jawab iya kalau jadi.` (`kunyalakan ulang` for `restart`, `kutidurkan` for `sleep`) and `Colokan PC mau kumatikan sekarang, Master? Listrik PC bisa langsung putus. Jawab iya kalau jadi.` (`kubalik` for `toggle`).
  - `discard_turn()`: drops this turn's request, for a turn that was rolled back: the owner never hears its question.
  - `awaiting_answer() -> bool`: whether the previous turn's request is waiting and this turn began within `window_s` of it.
- Thread-safe (a lock): turns come from the voice loop, but `respond` may run from other threads in tests.

Integration:
- `brain/tools.run_tool(..., *, confirmations: ConfirmationGate | None = None)`: `control_device` asks `confirmations.check(...)` after its arguments are valid and before `registry.execute`; a refusal is the result `{"ok": false, "needs_confirmation": true, "message": ...}` with `is_error` true (so an empty final reply never claims success). `list_devices` and other tools are unaffected. `held_for_yes(record) -> bool` tells such a held call apart in a turn's `ToolCallRecord`s.
- `ClaudeBrain` and `OllamaBrain` take `confirmations: ConfirmationGate | None = None`, call `begin_turn(user_text)` at the start of every `respond` (before the session check's reset, so a reset never forgets the turn), and pass it to `run_tool`. A session reset (idle or at the turn cap) waits one turn while `awaiting_answer()`, so the model still sees the question the owner is answering. A turn whose history is kept, canned replies included (the round limit, a cut-off reply, an empty reply), ends its spoken text with `with_question(...)`. Claude adds it to `BrainReply.text` only, so the history stays append-only and byte-identical (the tool result already quotes the question); Ollama also keeps it in the turn's assistant message. A rolled-back turn (an API error, a refusal, any exception) calls `discard_turn()` and speaks only its apology. When the model's final reply is empty, the fallback text leaves out held calls, whose message is for the model and is never spoken: when every call was held, the question is the whole reply. `build_brain` always gives them one gate, with `names=[assistant.name, *assistant.wake_words]` (the follow-up window and `waifu chat` pass her name along with the answer): confirmation is never off in `waifu run` or `waifu chat`.
- Not gated: `waifu device` (the owner typed the command), schedules and routines (they refuse these devices already), and the PC's own 30-second delay and `cancel_shutdown` stay as they are.
- Persona: the rule stays (turning the PC off waits for the owner's yes); it now says that the code asks the question, so the model calls `control_device` without asking first, never asks again or retries after `needs_confirmation`, calls the same command again only after the owner answers yes, and only one such command is asked per turn. The plug's device line says it needs the owner's confirmation first (no longer "ask first").

Safety: tests use mock devices and fake clocks; no test reaches a real power action (the conftest guards stay).

### looking at the screen (v1.10)

User story: "Cyrene, lihat layarku, menurutmu tim ini gimana?" / "liat deh build-ku" / "ini error apa ya, coba lihat" → she takes one screenshot of the main monitor, sees it, and answers about what is on it. She only ever looks when the owner's words in that same turn ask her to; she never looks by herself.

Non-goals: watching continuously or recording, reading other monitors, clicking or typing, looking with the Ollama backend (qwen3:8b has no vision; the tool is simply not offered), any game automation.

Privacy: the screenshot goes to the Claude API as part of the conversation (and stays in that session's history until the session ends, like everything else said); it is never written to disk or logged, not even with `-v` (the CLI holds the `anthropic` logger at INFO, since the SDK's DEBUG "Request options" record dumps every request, screenshots included), and she never saves what she sees as a memory note unless the owner asks. The README says so, and that she can only look when asked.

Config `vision` (committed with its tests before the parallel tasks): `enabled` (default true), `max_side` (default 1280 pixels for the longer side, 512-1568). API limits: an image's base64 data at most 5 MB (the smallest per-image limit of the platforms that serve Claude), a request at most 32 MB. `max_side` alone does not keep a PNG under 5 MB: a busy screen (a detailed game) barely compresses, so above about 1450 it may not fit, and the screen tool then takes it again smaller.

`screen.py` (no new dependency):
- `capture_screen(max_side) -> ScreenImage` (`ScreenImage(png: bytes, width: int, height: int)`): the primary monitor through GDI with ctypes — `user32.SetThreadDpiAwarenessContext(DPI_AWARENESS_CONTEXT_PER_MONITOR_AWARE)` first (python.exe is DPI-unaware, so on a scaled display `GetSystemMetrics` would report the smaller logical size while the screen DC stays physical, and only the top-left part would be copied; the thread's own context is restored last, after every handle), `GetSystemMetrics(SM_CXSCREEN/SM_CYSCREEN)`, `user32.GetDC(None)`, `gdi32.CreateCompatibleDC`, `CreateDIBSection` (32-bit top-down BGRA), `SetStretchBltMode(HALFTONE)` + `SetBrushOrgEx`, `StretchBlt(..., SRCCOPY | CAPTUREBLT)` straight into the scaled size (aspect kept, the longer side `max_side`, never upscaled), the pixels copied out with numpy, everything released in reverse order on every path. All libraries are loaded through `ctypes.WinDLL` with full `argtypes`/`restype`; a failing call raises `OSError` with `ctypes.get_last_error()`.
- `encode_png(rgb: numpy.ndarray) -> bytes`: an RGB PNG (IHDR, one IDAT compressed by `zlib` level 6, IEND, CRCs by `zlib.crc32`) whose rows are adaptively filtered (filter method 0): each row takes the filter type (None, Sub, Up, Average, Paeth) whose output bytes, read as signed, have the smallest sum of absolute values, the heuristic the PNG specification suggests, computed with numpy. Smooth screens shrink many times over; noise does not. Checked against the PNG spec in tests by decoding it back with `zlib` and undoing every filter type.
- A fullscreen-exclusive game may capture as black; the README says to use borderless/windowed mode, and the tool description lets her say so.

`brain/screen_tools.py` — `ScreenTools(*, capture=capture_screen, max_side=1280, names=())` (`names`: her name and wake words, as for the confirmation gate), a `ToolProvider` with one strict tool `look_at_screen {}`:
- Description (English, static so the prompt cache stays warm): take one screenshot of Master's main monitor to see what Master is showing; call it only when Master's current message asks to look at the screen; describe and answer about what is visible; never read out private details (messages, emails, account numbers) unless Master asks about them, and never save anything seen on the screen with `remember` unless Master asks; her own avatar may appear as an anime figure, usually in a corner (the capture includes layered windows): that is her, to be ignored unless Master asks; an all-black screenshot usually means a game in exclusive fullscreen: suggest borderless or windowed mode.
- `begin_turn(user_text)`: remembers whether the owner's words this turn ask to look: a word from `lihat`, `liat`, `lihatin`, `liatin`, `tengok`, `tengokin`, `layar`, `layarku`, `screen`, `screenshot`, `monitor`, `見て` (tokenized like `brain.confirm`, her names skipped). In a turn sent through the phone camera only the words naming the screen count (v1.15, `camera_turn`).
- `run("look_at_screen", {})`: when this turn did not ask, an error result telling the model Master did not ask to look in this message; otherwise it captures (a capture `OSError` becomes an Indonesian error result) and returns `{"ok": true, "width": w, "height": h}`, keeping the image for `take_images()`. At most one screenshot per turn (a second call in the same turn is an error result). A screenshot whose base64 data is over 5 MB is taken once more, its `max_side` the longer side times the square root of 5 MB over its size, times 0.9 (PNG size follows the pixel count); when that one is still over 5 MB, the result is the Indonesian error `Layar tidak bisa dilihat: gambarnya terlalu besar untuk dikirim.` without an image.
- `take_images() -> list[ToolImage]`: hands over (and forgets) the image of the last successful run. `ToolImage(media_type="image/png", data=bytes)` lives in `brain/base.py`.

Brains:
- Optional provider hooks, used only when a provider has them (duck-typed; the `ToolProvider` protocol itself is unchanged): both brains call `provider.begin_turn(user_text)` at the start of every `respond`, next to the confirmation gate.
- `ClaudeBrain`: after running a tool call, it asks every provider with `take_images` for images and, when there are any, sends that call's `tool_result` content as a list: the text block with the JSON, then one `{"type": "image", "source": {"type": "base64", "media_type": ..., "data": ...}}` block per image. The history keeps exactly what was sent (append-only). Every request resends the session's images, so when the images in the history hold 10 MiB of base64 data or more, the next turn starts a new session, like an idle one (and, like it, waits one turn while a confirmation question awaits its answer), and at 20 MiB it starts one even while a question awaits: requests then stay under the 32 MB limit, where the API would refuse every later turn of the session (the arithmetic, with the phone camera's photos, is in v1.15). The size is read from the history itself, so a rolled-back look does not count.
- `OllamaBrain` never gets `ScreenTools` (the factory does not add it), so it needs no image support.

CLI: `run` and `chat` add `ScreenTools(max_side=config.vision.max_side, names=[assistant.name, *assistant.wake_words])` to the providers when `vision.enabled` and `brain.backend` is `claude`; `check` reports `✓ Melihat layar: aktif (Claude)`, `! Melihat layar: tidak tersedia dengan Ollama`, or `! Melihat layar mati`. Logging holds the `anthropic` logger at INFO even with `-v` (see Privacy). README (Indonesian) section "Melihat layar" with examples, privacy, that her mascot appears in the screenshot (move it with `avatar.corner` or by dragging, or close it, when that corner matters), that a session restarts after many busy screenshots, the borderless-mode tip, and how to turn it off.

Safety: tests never capture the real screen: `tests/conftest.py` is strengthened (never weakened) to refuse `BitBlt`, `StretchBlt` (gdi32) and `PrintWindow` (user32) through `ctypes.WinDLL` and `ctypes.windll`; `capture_screen` is injected as a fake in every test; `tests/test_safety_guard.py` covers the new guards.

### cutting her off (v1.11)

User story: Cyrene is reading out a long answer, an announcement, or a reminder; the owner double-clicks her avatar → she stops at once and listens (the follow-up window opens and the avatar shows listening), so the owner can talk right away without the wake word. A double-click while she is not speaking works as before (she listens and says a `listen` line). Without the avatar nothing changes.

Non-goals: stopping her by voice while she speaks (the microphone is paused during her speech so she never hears herself; voice barge-in needs echo cancellation), a keyboard shortcut, cancelling a reply that is still being thought up (only speech that is playing is cut), resuming a cut-off reply.

`voice/audio.Player`:
- `play(audio, sample_rate) -> bool`: True when the clip played to the end, False when `stop()` cut it.
- `stop() -> bool`: safe from any thread and never blocks; asks `play` to cut the clip being played and returns True, or returns False when nothing is playing. It makes no PortAudio call itself: only the thread in `play` touches the stream. (In sounddevice 0.5.6 `wait()` closes the stream once the finished callback fires, and PortAudio fires it from inside the `Pa_StopStream` of `sounddevice.stop()`, so a stop from another thread would stop and close the same stream while `wait()` closes it: a use-after-free or double free.) `play` starts the clip with `sounddevice.play`, watches `sounddevice.get_stream().active` every 50 ms and the cut request (which wakes it at once), and then always calls `sounddevice.stop()` (stop and close) on its own thread, whether the clip played out or was cut. A `stop()` racing the clip's end counts as a cut on both sides; each `play` starts with no request, so a late `stop()` never cuts the next clip.

`app.Assistant`:
- `interrupt() -> bool`: safe from any thread and never blocks; stops whatever she is saying (a reply, an announcement, a reaction) through the player. True when something was playing. The interrupted `speak` finishes as usual (microphone resumed, segmenter reset, the follow-up window opened after a reply); it logs that the speech was cut.
- Speech that was cut holds queued announcements back, so a reminder queued during the cut speech never pauses the microphone again before Master has talked: `run` says them only once Master's next words have been accepted (by the wake word or the follow-up window, after that reply as usual) or `followup_seconds` after the cut have passed. The hold is set on the speaking thread before the microphone resumes, timed on the constructor's `clock` (default `time.monotonic`, the gate's clock).
- `speaking` (property): True only while a clip is playing (narrower than `busy`, which also covers thinking).

`avatar/interactions.InteractionHandler` gains `interrupt: Callable[[], bool]` (constructor keyword, default a function returning False):
- `handle("double_click")`, when the switch is on: calls `interrupt()` right away on the calling thread (it never blocks); when that stopped her speech, it queues an internal `listen_after_cut` instead of `double_click`. The worker answers it with `listen()` only (no `listen` line, no cooldown, not skipped while busy: `listen_now` waits for the cut speech to finish and then opens the window).
- Everything else is unchanged; a double-click while she is busy thinking (not speaking) is still ignored.

Avatar page (both renderers, `live2d.js` and `avatar.js`): `setState(state)` with any state other than `speaking` ends the current speak track at once (`logic.speechAfterState(speech, state)`), so the mouth closes when she is cut off (the track would otherwise run to its planned end), and ends the track's own emotion 1.5 s later (`logic.emotionEndAfterState(emotionUntilS, speech, state, nowS, tailS)`, the same tail as after a full reply) instead of after the speech's planned end; an emotion set after the speech started (an emotion event, a click's feedback face) keeps its own end. A speak track remembers the emotion end it set (`speech.emotionUntilS`) to tell its emotion apart. A normal reply's track has ended by the time `idle`/`listening` arrives, so nothing else changes.

CLI: `run` passes `interrupt=assistant.interrupt` to the handler; `waifu avatar` (no voice) passes nothing. README (Indonesian): "double-click Cyrene while she is talking to cut her off; she listens right away".

Safety: tests use a fake `sounddevice` module and fake players; nothing plays or records real audio.

### morning briefing (v1.12)

User stories:

1. Once a day, the first time she is running between `briefing.time` (default 07:00) and `briefing.until` (default 12:00), she greets the owner by herself and sums up the day in a few sentences: the weather, today's schedules and reminders, her games when the gacha buddy is on, and whatever her memory holds for today (a birthday, an exam). The same text goes to the phone when notifications are on.
2. "Cyrene, cuaca hari ini gimana?" / "ringkasan hari ini?" / "hari ini ada jadwal apa?" → the same data on request, any time of day.
3. A restart, or a second PC start the same morning, never repeats the greeting.

Non-goals: news, traffic, calendars outside Cyrene, holidays, multi-day forecasts beyond today and tomorrow morning, a greeting without `waifu run` running.

Weather: Open-Meteo (free, no account or key; `https://api.open-meteo.com/v1/forecast` and `https://geocoding-api.open-meteo.com/v1/search`), reached only from `waifu run`/`chat`/`briefing`, never from tests (the conftest internet guard).

Config `briefing` (committed with its tests before the parallel tasks): `enabled` (default true), `time` (default `07:00`), `until` (default `12:00`, after `time`), `city` (default none; for example "Bandung"), `latitude`/`longitude` (default none; both or neither; when set they win over `city`, which then only names the place), `push` (default true: also send the greeting to the phone when `notify` is on), `state_path` (default `data/briefing.json`).

`weather.py`:
- `Weather` (frozen dataclass): `place: str`, `condition: str` (Indonesian, from the WMO weather code: 0 cerah, 1 cerah berawan, 2 berawan, 3 mendung, 45/48 berkabut, 51-57 gerimis, 61-67 hujan (65/67 deras), 80-82 hujan lokal (82 deras), 95-99 badai petir, 71-77/85-86 salju; anything else "tidak diketahui"), `temperature_c: float` (now), `min_c`/`max_c: float` (today), `rain_chance: int` (today's maximum precipitation probability, %), `tomorrow_morning: str` (condition at 07:00 tomorrow).
- `WeatherError(Exception)`: Indonesian, speakable.
- `WeatherClient(*, latitude=None, longitude=None, city=None, fetch=<urllib JSON GET with a User-Agent, called as fetch(url, timeout_s)>, clock=time.monotonic)`: `today() -> Weather`. With coordinates the place is the city when one is set (what she says), else `"<lat>, <lon>"`; no geocoding. With only a city it geocodes it once (`name=<city>&count=1&language=id`), caching the result for the client's life; no result → `WeatherError("Kota <city> tidak ditemukan ...")`. She is silent while it runs, so one `today()` call has 8 s for the city lookup and the forecast together: each request's timeout is the time left (urllib's socket timeout: per connection and per read, not the name lookup), and a request with less than 1 s left is not made (`WeatherError`, the unreachable message). The forecast request uses `current=temperature_2m,weather_code`, `daily=weather_code,temperature_2m_max,temperature_2m_min,precipitation_probability_max`, `hourly=weather_code`, `timezone=auto`, `forecast_days=2`. Network or format problems → `WeatherError`. No location configured → `WeatherError` saying how to set `briefing.city`.

`briefing.py`:
- `BriefingTools(*, weather: WeatherClient | None, schedule: ScheduleStore | None, now=datetime.now)`, a `ToolProvider` with one strict tool `daily_briefing {}` (English description: today's date and weekday, the weather where Master lives, and today's schedule entries; use it for greetings, "how's the weather", "what's on today"; for games call game_status too when it exists; mention what memory holds for today). Result JSON: `{"date": "Selasa, 13-10-2026", "weather": {...} | null, "weather_problem": str | null, "schedule_today": [{"time": "15:00", "what": "<Indonesian>"}...]}`; a weather or schedule failure fills its `*_problem` field instead of failing the tool. `run` never raises.
- `BriefingTimer(config: BriefingConfig, *, request: Callable[[str], None], now=datetime.now, tick_seconds=30)`: a daemon thread (`start`/`stop`/context manager/`tick_once()` like the scheduler). On a tick where `time <= now.time() < until` and the state file's `last_date` is not today, it writes today's date first (atomic, so a crash never repeats it) and then calls `request(BRIEFING_PROMPT)`. A corrupt state file is moved aside like the other stores. `BRIEFING_PROMPT` (Indonesian) tells the model this is her own morning greeting, not something Master said: greet Master warmly for the time of day, call `daily_briefing` (and `game_status` when available), and sum up the day in 2-4 short sentences, mentioning anything from memory that matters today. It contains no word that would open the screen tool's gate or count as a yes.

`app.Assistant.ask_aloud(prompt: str, *, on_reply: Callable[[str], None] | None = None, required_tool: str | None = None) -> None`: safe from any thread; queues the request. `run` handles queued requests one at a time between utterances like announcements (never during a reply, while Master speaks, or while announcements are held after a cut), and also never on the frame that said announcements (the next frame checks again that Master is not speaking and did not cut them short) and never while the follow-up window last opened (after a reply, a reaction, or a double-click) is still open, timed on the Assistant's clock: Master may still answer, so a conversation is never taken over and a request waits until the window has closed. It asks the brain (`_think(prompt)` inside `_engaged`), speaks the reply like a reply (follow-up window open, so Master can answer without the wake word), and passes the spoken text to `on_reply` on a short-lived daemon thread of its own (a push may take its whole timeout; the voice loop goes straight back to the microphone; a failure there is logged). A brain answers a failure with an apology, never an exception: with `required_tool`, a reply whose turn has no successful call of that tool (an apology, an empty or tag-only reply, another tool) is logged, the avatar returns to idle, and nothing is said or passed on. (A turn that called the tool and then failed still apologises; telling that apart needs a failure flag on `BrainReply`, a `base.py` contract change not made here.)

CLI:
- `run`: when `briefing.enabled`, `BriefingTools` joins the providers and a `BriefingTimer` runs for the voice loop's lifetime, its `request` calling `assistant.ask_aloud(prompt, on_reply=<push to the phone when briefing.push and a notifier exists>, required_tool="daily_briefing")`. `chat`: the tools only (no timer).
- `waifu briefing`: prints today's briefing data (date, weather or its problem, schedule or its problem) without the brain; exit 1 when the weather or the schedule fails.
- `check`: `✓ Sapaan pagi: jam 07:00-12:00, cuaca untuk <place>` (`<city>`, `<lat>, <lon>`, or `<city> (<lat>, <lon>)` when both are set), `! Sapaan pagi: cuaca belum diatur (isi briefing.city)`, or `! Sapaan pagi mati`; no network call.
- README (Indonesian) section "Sapaan pagi dan ringkasan harian"; `config.example.yaml` documents `briefing`.

Safety: tests never reach the internet (fake fetch; the conftest guard), never sleep for real, and never touch `data/`.

### API cost monitor (v1.13)

User stories:

1. "Cyrene, biaya API bulan ini berapa?" / "hari ini sudah habis berapa?" → tokens and the estimated cost in US dollars (and rupiah when `usage.idr_per_usd` is set), from her own records.

Prices (USD per million tokens, from the claude-api reference, overridable in config): `claude-opus-5-5`: input 4.00, output 20.00, cache write (5-minute TTL, the automatic cache she uses) 5.00, cache read 0.20. A response from a model not in the table (a server-side fallback) is priced with `usage.default_model`'s prices and counted as estimated. `usage.default_model` must itself have prices (built in or in `usage.prices`): otherwise such responses would cost nothing under a green `check` and no budget notice would come, so the ledger refuses it as a configuration problem.

Config `usage` (committed with its tests before the parallel tasks): `enabled` (default true), `path` (default `data/usage.json`), `monthly_budget_usd` (default none, > 0), `idr_per_usd` (default none, > 0), `prices` (mapping model id → `{input, output, cache_write, cache_read}` USD per MTok, merged over the built-in table), `default_model` (default `claude-opus-5-5`).

`usage.py`:
- `TokenUsage` (frozen dataclass): `input`, `output`, `cache_write`, `cache_read` (ints) from a response's `usage` or one entry of its `usage.iterations` (`input_tokens`, `output_tokens`, `cache_creation_input_tokens`, `cache_read_input_tokens`; missing or None counts 0).
- `cost_usd(model, tokens, prices, default_model) -> tuple[float, bool]` (the cost and whether it was estimated with another model's prices; `default_model` must be in `prices`).
- `UsageLedger(path, *, prices, default_model, now=datetime.now)` raises `ConfigError` (naming `usage.default_model` and `usage.prices`) when `default_model` has no prices in the merged table: `run`, `chat`, and `waifu usage` then stop with the configuration problem (exit 2) and `check` shows `✗ Biaya API: <the problem>`. `record(model, tokens)` adds one billed model attempt to that local day's per-model totals (tokens, requests, cost): `requests` counts attempts, so a server-side fallback's declined attempt is a request of its own; `day(date)`, `month(year, month)` → `UsageSummary(requests, tokens: TokenUsage, cost_usd, estimated: bool, by_day: list[...])`. File rules as the other stores (re-read, lock, atomic replace, corrupt file moved aside, never created by reading). `budget_notices(budget_usd) -> list[str]` returns the 80 % / 100 % notices not yet given this month (and marks them given in the same file).

Brains: `ClaudeBrain(..., on_usage: Callable[[str, TokenUsage], None] | None = None)` calls `on_usage(model, tokens)` after every `messages.create` (every tool round too, and a refused response), once for each model attempt the response billed. After a server-side fallback the top-level `usage` covers only the attempt that produced the message, and `usage.iterations` is the per-attempt record (a declined attempt bills at normal rates): when it holds `message` or `fallback_message` entries, each is reported with its own model (the request's model when a `message` entry names none) and its own counts; otherwise once with `response.model` and the top-level `usage`. An exception in it is logged and ignored. The request is unchanged.

`brain/usage_tools.py` — `UsageTools(ledger, *, idr_per_usd=None, now=...)` with the strict tool `api_usage {period: "today" | "month"}` → `{"period", "requests", "input_tokens", "output_tokens", "cache_read_tokens", "cache_write_tokens", "cost_usd", "cost_idr" | null, "estimated"}`; the description says these are her own estimates.

CLI: `run`/`chat` with the Claude backend and `usage.enabled`: one ledger, `on_usage=ledger.record` into `build_brain`, `UsageTools` in the providers; in `run`, after each recorded response, budget notices (if any) are announced (`assistant.announce(notice, "surprised", wait_for_followup=True)`) and pushed. Network and security:
- The phone server listens on `127.0.0.1:<phone.port>` only (default 9883). Tailscale exposes it: the owner runs once `tailscale serve --bg --https=443 http://127.0.0.1:9883` (Tailscale terminates HTTPS with a real certificate for the machine's `*.ts.net` name and lets only the owner's tailnet devices in). `waifu phone setup` checks that the Tailscale CLI exists, reads the machine's DNS name from `tailscale status --json` (`Self.DNSName`), and prints the exact command and URL; it never changes Tailscale settings itself.
- Host check: every request's `Host` must be `phone.host` (the `*.ts.net` name; printed by `waifu phone setup`, written into config.yaml by the owner: setup never writes config.yaml), `127.0.0.1:<port>`, or `localhost:<port>`; anything else is 403. A request carrying `Tailscale-Funnel-Request` (Tailscale adds it to everything `tailscale funnel` brings in from the internet) is 403 too: the server is for the tailnet only. State-changing requests (POST) also need an `Origin` that matches the same set with https for the ts.net name (403 otherwise).
- Pairing: `waifu phone pair` creates a 6-digit code valid 10 minutes (stored hashed in `data/phone.json`, so the running `waifu run` sees it) and prints it. Every change of that file holds an OS lock on `data/phone.json.lock` from its read to its write, so `waifu phone forget` and a write of `waifu run` never undo each other. The page's pairing form submits it; a right code (constant-time compare, at most 5 tries per 10 minutes, then the code is burned) creates a device: a random 32-byte token returned once in a cookie `cyrene_device` (HttpOnly, Secure, SameSite=Strict, Path=/, Max-Age one year), stored only as a SHA-256 hash with a name ("Android"), created and last-used times. A wrong or expired code is 403; the try that burns the code, and a try while no code waits within 10 minutes after a burn, are 429 (make a new code). Every other route needs a valid device cookie (401 otherwise; the page then shows the pairing form); up to 4 `cyrene_device` cookies of a request are tried, so one planted by another page of the same site never hides the real one. `waifu phone devices` lists devices, `waifu phone forget <id>` revokes one.
- Requests are size-limited (chat text 2000 characters, audio 2 MB / 60 s) and rate-limited (at most one chat or talk at a time per device; 429 while one is running).

Phone server (`phone/server.py`, stdlib `ThreadingHTTPServer` like the avatar server, its own class, `start`/`stop`/context manager, port 0 in tests):
- `GET /` the page; `GET /manifest.webmanifest`, `/sw.js`, `/icon-192.png`, `/icon-512.png` (PWA); `GET /config.json` (engine, model URL or null without `avatar.model`, core URL, credit, owner_call, name; no secrets); the avatar's web files, vendored libraries, Live2D model files, and the Cubism Core, served from the same sources as the avatar server (shared helpers, the same traversal protection), all behind the device cookie. Served files other than the page carry `Last-Modified` with `Cache-Control: no-cache`, and an `If-Modified-Since` not older than the file gets 304 without a body, so the phone downloads the model (~40 MB) once; the page and every JSON answer are `no-store`.
- `POST /pair {code}` → 204 with the cookie, or 403/429.
- `POST /chat {text}` → `{"text", "emotion", "audio": <base64 WAV or null>, "fps", "visemes", "duration"}`.
- `POST /talk` (body `audio/wav`, mono 16-bit PCM at 16 kHz encoded by the page) → `{"heard": <transcript>, ...the /chat fields}`; an empty transcript answers `{"heard": "", "text": null}`.
- Backend protocol `PhoneBackend`: `chat(text) -> PhoneReply`, `transcribe(wav_bytes) -> str`; the server never touches the brain, STT, or TTS directly.

Assistant integration (`app.py`): `Assistant.reply_for_phone(text) -> PhoneReply`: the brain turn runs under the same lock as the voice loop's turns (one turn at a time, history append-only); the reply is NOT spoken on the PC; her TTS (edge-tts + RVC) synthesizes it, `avatar/lipsync.viseme_track` makes the mouth track, and the audio is returned as 16-bit WAV (resampled to 24 kHz). Speaker verification and the wake word are skipped for phone audio (the device is paired; the PC voiceprint does not fit a phone microphone). Phone turns count as turns for the confirmation gate and the screen gate like any other; a message sent with the phone's viewfinder open lets her look at the PC screen only by naming it (v1.15).

Page (`avatar/web/phone/`): reuses `live2d.js` (or `avatar.js` for VRM) for the avatar, full screen, upper framing; a chat strip (last few bubbles), a text box, and a hold-to-talk button (Web Audio capture → 16 kHz mono WAV in JS; released → POST /talk); plays the reply with Web Audio after the first touch (Android autoplay rule) and drives the mouth with the returned visemes via the renderer's existing `speak(event)`; shows thinking/listening states; a pairing screen when the cookie is missing; the chat alone, with a note, when `/config.json` has no model. A new reply scrolls the chat to its first line; a state change never moves the chat. The service worker keeps the page's own files network first and opens the kept copy offline or on a 5xx (tailscale serve answers 502 while `waifu run` is stopped); a 502/503/504 from any route reads as "cannot reach the PC". Pure helpers (downsampling, WAV encoding, response handling) live in a module with `node --test` coverage.

Config `phone` (committed with its tests before the parallel tasks): `enabled` (default false), `port` (default 9883), `host` (the ts.net name, default none), `state_path` (default `data/phone.json`).

CLI: `run` starts the phone server when `phone.enabled` (with the Assistant as the backend); `waifu phone setup | pair | devices | forget <id>`; `check` reports the server, Tailscale (CLI found, logged in, serve configured for the port, and a failure when Funnel is on for that name's port 443), `phone.host`, a warning without `avatar.model`, and the paired devices. README (Indonesian): installing Tailscale on PC and Android, enabling HTTPS certificates in the Tailscale admin console, `waifu phone setup`, `tailscale serve`, pairing, installing the page to the home screen, privacy (the model and voice stay on the owner's devices; replies go through Claude as usual).

Config: `phone.camera` (default true; committed with its tests before the parallel tasks). The camera is offered only when `phone.camera`, `vision.enabled`, and `brain.backend == "claude"`; photos are scaled by the page so the longer side is at most `vision.max_side`.

Brain (`brain/attachments.py`, `brain/claude.py`, `brain/screen_tools.py`):
- `TurnImages` (thread-safe): `put(image: ToolImage)` (at most one waiting; a second put replaces it), `take() -> list[ToolImage]` (hands over and forgets), `clear()`. The Assistant and the Claude brain share one through constructor injection: `ClaudeBrain(..., turn_images: TurnImages | None = None)`. The `Brain` contract in `brain/base.py` is unchanged.
- `CameraTurn` (thread-safe): `begin()`, `end()`, `active -> bool`: whether the brain turn under way was sent through the phone camera. The Assistant and the screen tool share one through constructor injection: `ScreenTools(..., camera_turn: CameraTurn | None = None)`. `ScreenTools.begin_turn` reads it: in a camera turn only the words naming the screen (`layar`, `layarku`, `screen`, `screenshot`, `monitor`) ask her to look, and `look_at_screen` otherwise answers with an Indonesian error saying the message was sent with the phone camera open, that what Master shows is on the camera and not on the PC screen (and that a message without a photo lost it), and to look at the PC screen only when Master names it. - `ClaudeBrain.respond`: right after the providers' `begin_turn`, takes the turn images. With none, the user message is the plain string as today (requests byte-identical to v1.14, the cache stays warm). With one, the user message content is a list: the image block (base64, its media type), a text block `[Foto dari kamera HP {owner}, diambil saat pesan ini dikirim: inilah yang {owner} tunjukkan. Jangan simpan isinya dengan remember kecuali diminta.]` (`{owner}` = owner_call), then the turn's text block (`format_user_turn` as today). The history keeps it exactly as sent; a rolled-back turn drops it with the rest.
- `_image_bytes` counts the base64 data of images both inside tool results and directly in user messages (today it would raise `KeyError` on a user message whose list holds an image or text block instead of tool results); its log says "images" instead of "screenshots".
- The session's images (the v1.10 rule, now covering photos): the API refuses a request over 32 MB (taken as 32,000,000 bytes). One turn adds at most one photo (3.5 MiB, 4,893,356 bytes as base64) and one screenshot (5 MiB as base64), 9.67 MiB together. A session whose history holds 10 MiB of base64 image data or more ends before the next turn, so the turn that crosses it ends under 19.67 MiB; while a confirmation question awaits its answer the session waits one turn, which may add as much again: 10 + 2 x 9.67 MiB = 30.76 MB plus the text. That turn may ask a question of its own, and so on, so at 20 MiB the session ends before the turn even while a question awaits, and the gate forgets that question (`ConfirmationGate.forget_question()`: the new session never saw it), so Master's yes there runs nothing, not even the very call it was asked about. No turn starts with 20 MiB of images or more, so the largest request stays under 20 + 9.67 MiB = 31.1 MB.
- `OllamaBrain` gets no `TurnImages` (the factory never passes one) and needs no change.

Phone server (`phone/server.py`, `phone/jpeg.py`):
- `PhoneServer(..., camera_max_side: int | None = None)`: None means the camera is off. `/config.json` gains `"camera": {"enabled": bool, "max_side": int | null}`.
- `POST /chat` accepts an optional `"image"` (base64 JPEG string) and an optional `"camera"` (a JSON boolean: the message was sent with the viewfinder open, also when it carries no photo) next to `"text"`. `POST /talk` accepts, besides the `audio/wav` body of v1.14, `application/json` `{"audio": <base64 WAV>, "camera": true, "image": <base64 JPEG>}` (`camera` and `image` optional); the decoded WAV is checked exactly as the binary body is. A `camera` that is not a boolean (or an `image` that is not a string) is 400 `Permintaan tidak valid.`. A message is sent through the camera when `camera` is true or it carries a photo. The body limit is chosen from the Content-Type before the body is read: with the camera on, 5 MB for /chat JSON and 8 MB for /talk JSON (the 2 MB recording and a 3.5 MB photo as base64); the v1.14 limits otherwise and for `audio/wav`.
- A message sent through the camera, with or without a photo, is accepted only when the camera is on (otherwise 400 `Kamera HP tidak aktif.`; the limits are chosen before the body is read, so a page loaded before the camera was turned off may get 413 for a large body instead). A photo decodes as strict base64 (`base64.b64decode(..., validate=True)`), is at most 3.5 MB decoded (its base64 then stays under the API's 5 MB image limit), starts with the JPEG SOI marker `FF D8 FF`, and `jpeg.jpeg_size(data) -> tuple[int, int]` (walks the marker segments to the first SOF0-SOF15 frame header except DHT `C4`, JPG `C8`, and DAC `CC`; raises `ValueError` on truncated data, a missing frame header, or a zero size) reads a longer side between 16 and `camera_max_side` pixels and a shorter side of at least 16; anything else is 400 `Foto tidak valid.`.
- `PhoneBackend.chat(text, image: bytes | None = None, *, camera: bool = False) -> PhoneReply` (JPEG bytes); `transcribe` is unchanged. A message not sent through the camera is the v1.14 call `chat(text)`; one sent through it is `chat(text, image=<the photo or None>, camera=True)`. The server passes the photo through untouched and logs only its byte size and dimensions.

Assistant (`app.py`): `reply_for_phone(text, image: bytes | None = None, *, camera: bool = False)` and `PhoneAnswers.chat(text, image=None, *, camera=False)`. Inside the turn lock, right before the brain turn, the photo (`ToolImage("image/jpeg", data)`) is put into the shared `TurnImages`, and the holder is cleared in a `finally` after it, so a failed turn never leaks it into the next one (a voice turn included). Without a `TurnImages` (camera off, Ollama) a photo is dropped with a warning. The voice loop never puts images. In the same way, a phone turn sent through the camera (`camera`, or any photo) is marked in the shared `CameraTurn` (`begin()` right before the brain turn, `end()` in a `finally`), so only that turn is a camera turn; voice turns, text-chat turns, briefings, and phone messages sent without the viewfinder never are. `run` creates one `TurnImages` and one `CameraTurn` when the camera is offered and passes the first to the Claude brain, the Assistant, and (as `camera_max_side=vision.max_side`) the phone server, the second to the screen tool and the Assistant.

Page (`avatar/web/phone/`):

With `name`: matched after NFKD + casefold with punctuation and spaces removed, exact first, then substring, at most 3 characters (both March 7th Paths and the Trailblazer's Paths come back together, told apart by `path`): `{"as_of", "query", "characters": [{"name", "rarity", "level", "eidolon", "path", "element", "light_cone"?: {"name", "level", "superimposition", "rarity"}, "stats": {...at most 14}, "relics": [{"piece", "main", "value", "level"} ...at most 6], "memosprite"?}]}`, each at most 1.5 kB; no match: `"characters": []` and `"close"`: up to 3 `difflib.get_close_matches` names (not an error: a name misheard by the STT still resolves).

- `hsr_events {}`: `{"as_of", "version"?, "warps": [{"type", "name", "featured", "four_stars", "starts"?, "starts_in_hours"?, "ends"?, "ends_in_hours"?}], "events": [{"name", "ends"?, "ends_in_hours"?, "current"?, "total"?, "done"}], "endgame": [{"mode", "name", "ends"?, "ends_in_hours"?, "current"?, "total"?}]}`; at most 8 warps, 15 events (soonest end first, names cut to 60 characters), 4 endgame windows; rewards, descriptions, and icons never; fits in 3 kB.
- Times are local (`YYYY-MM-DD HH:MM`, `as_of` the fetch time), `ends_in_hours`/`starts_in_hours` rounded up and never below 0, computed when answering so a cached result stays right. Compact JSON, `ensure_ascii=False`. A `GachaError` becomes `{"ok": false, "message"}` with is_error; invalid arguments and unknown names as in `GachaTools`; `run` never raises.
- An in-memory cache per process, keyed `characters`, `endgame:<mode>`, `calendar`, with TTLs of 15, 10, and 60 minutes, holding only successes; asking for every mode reuses the fresh modes and fetches only the stale ones. A lock guards the cache, never held during a fetch (voice and phone turns run on different threads).
- Descriptions say: use it instead of guessing; answer only what was asked in one or two short sentences, at most about three names, no lists or parentheses (her TTS drops parenthesized asides); keep the official English terms (Eidolon, Light Cone, Superimposition, Memory of Chaos); comment only from the returned data and say so when a character or Light Cone is new to her; never claim how many stars are missing; present banners only as information; never suggest pulling, spending money, or topping up; do not save the data with `remember` unless Master asks.

## Code Style

See `CLAUDE.md` → Code Conventions and Patterns. Dataclasses for value

## Testing Strategy

- `pytest`, one `tests/test_<package>_<module>.py` per module, run without network, GPU, mic, or speakers.
- Fakes at the vendor boundary: fake tinytuya objects, fake `broadlink` device, fake `subprocess.run`, fake Anthropic client returning SDK-shaped objects (`SimpleNamespace` with `.type`, `.content`, `.stop_reason`), fake ollama client, fake embedder, fake Whisper model, fake `sounddevice`.
- Pure logic (segmenter, gate, language split, cosine, session reset, fallback echo rule, append-only history) gets direct unit tests with synthetic inputs.
- Every task ends with the full suite green and `ruff check` + `ruff format --check` clean.
- Hardware/GPU verification is a separate manual checklist in `README.md`, not part of the suite.

## Boundaries

- Always: lazy-import heavy libraries; verify vendor APIs against installed source; keep spoken text free of markdown/emoji; keep Claude history append-only.
- Ask first: new dependencies, multi-GB downloads, changes to `base.py` contracts.
- Never: commit `config.yaml`, `data/`, `models/`, keys; power off the real PC from tests; let an exception escape `Brain.respond` or `DeviceRegistry.execute`; log or commit the HoYoLAB cookie, an authkey, the ntfy topic, or gacha history; automate gameplay.

## Success Criteria

1. `pytest` and `ruff` are clean on a machine with only the core dependencies.
2. `waifu chat --dry-run` with the Ollama or Claude backend turns "nyalakan lampu kamar dan AC 24 derajat" into `control_device` calls on the mock devices and a short spoken-style reply.
3. `waifu say "Halo Master, おかえりなさい!"` produces Indonesian then Japanese speech.
4. With the voice extra installed: `waifu check` reports CUDA and the Whisper/ECAPA libraries as importable (models load on first `run`/`enroll`); `waifu enroll` then `waifu speaker-test` separates the owner from another voice.
5. `waifu run` completes user stories 1–5 on real hardware (manual checklist).
6. v1.4: `pytest` (no internet) and ruff are clean; `waifu gacha history hsr --full` imports the owner's real HSR history with the cached authkey and the pity matches the game; with the cookie, `waifu gacha status` and `waifu gacha checkin` work for all three games; `waifu notify-test` reaches the owner's phone; in `waifu run` a reminder is spoken and pushed once (manual).
